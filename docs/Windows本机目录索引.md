# Windows 本机目录恢复与后台扫描

本页描述 v1.0.1 的 Windows 启动修复；发布准备时安装包尚待构建，实际测试、打包与发布状态见 [1.0.1 发布记录](releases/1.0.1.md)。

## 启动与界面

Windows 启动先恢复设置及对端离线相册，再开启 gRPC 与 mDNS / DNS-SD。共享目录的本机索引在后台恢复并核对，不再把整个扫描包含在界面的全局忙状态中。设备在线核验、手动连接、设置及目录增删可以继续工作；共享目录区显示独立的检查状态。

此前每次启动都会在监听 gRPC 之前完整扫描共享目录，本机索引又仅保存在进程内，因此重启后的扫描期间不能供对端下载，设备发现尚未启动，目录操作也会一直禁用。新流程将网络可达、目录可用和扫描进行中分开处理。

首次运行修复版本没有本机索引缓存，仍需完成一次扫描才能共享媒体。此时身份请求可用，但目录和文件请求明确返回暂不可用，不把未完成扫描当作空目录，不让对端误删离线相册。之后启动从缓存恢复完整目录，对端可以在后台核对期间继续下载；每次读取仍检查文件状态及目录访问权限。

扫描仍完整遍历轻量文件元数据，以发现应用退出期间的增删；本次没有引入文件监控或 USN 增量日志。ARW 只在此阶段读取文件名、大小、修改时间等信息，不解码原图、生成全库缩略图或哈希原文件内容。扫描复用已固定的父目录句柄，避免为每个文件重复打开整条目录链。

## 索引缓存与数据保留

本机索引单独保存在应用数据目录内的 `catalog/local-catalog.bin`，格式版本为 1，不改动媒体库 schema 7、下载任务库 schema 3、现有设置及 gRPC v4。索引限制为 512 MiB、100 万条，超限提示缓存不可用而继续提供当前完整扫描结果；未来格式变更须提供迁移或保留原文件并安全拒绝。

- 缓存包含版本、共享目录配置和媒体轻量元数据；不保存缩略图或原文件内容。只有共享根配置完全匹配时才能恢复为完整目录。
- 恢复核验共享根可访问，并从当前共享根和经过校验的相对路径重新构造文件位置。缓存中的索引不能绕过路径、重解析点、大小及修改时间检查；已删除或变化的文件仍拒绝按旧信息下载。
- 完整扫描成功后原子替换索引缓存；写入失败会提示，但不会撤销已经扫描成功的共享目录。扫描失败或被取消不能把未完成结果发布为正式目录。
- 损坏或较新版本的缓存保留原文件并报告错误，当前进程停止覆盖该缓存，继续通过完整扫描提供共享。不会清空原有数据库、下载分片或用户媒体。

## 并发与撤销

普通重扫保留上次完整目录，新结果经校验、排序、目录摘要计算后整体发布。Dart 的大目录整理在独立 isolate 中执行，平台结果到模型的转换分批让出执行权；跨平台协议的排序及 revision 算法保持一致。

扫描与恢复都有代次校验。共享目录变更立即淘汰旧任务，被移除的目录停止提供文件；仍共享目录中的旧文件继续可读。新目录配置尚未完整扫描时，目录分页暂不可用，避免发布不完整的组合快照。停止共享或退出时撤销正在恢复、扫描的任务，迟到结果不能重启监听或覆盖新状态；停止共享不会删除持久索引。

Android 的后台共享就绪握手保持原来的完整扫描要求；本次仅 Windows 启用提前监听、后台恢复模式。其他平台沿用原有启动流程，公共目录摘要处理与协议行为有回归覆盖。

## 验证边界

自动化覆盖慢启动、无缓存与恢复缓存、万张 ARW 规模的轻量元数据、扫描期间 gRPC 下载和设备发现、目录增删、生命周期取消、权限失败与缓存异常。Windows 原生测试覆盖持久索引、安全恢复、版本保护、原子替换及取消边界。

2026-10-28 开发阶段在规定的 Flutter 3.47.6 / Dart 3.13.5 环境完成格式检查、静态分析和全量 Flutter 测试（1076 项，含覆盖率），Windows 源码交接检查 7 项通过。新增 Windows 原生索引测试 12 项已注册到 CTest；该次开发检查没有 Windows 编译运行环境，未执行这些原生测试或构建 Windows 安装包。上述结果不代替 v1.0.1 发布提交的完整检查，本次发布结果统一记录在 [1.0.1 发布记录](releases/1.0.1.md)。

平台通道仍一次传回完整轻量元数据，编解码大消息可能出现短时卡帧；本次解除启动依赖并移出大目录排序与摘要工作，不承诺未经实机测量的帧率或启动耗时。

本机运行的 Flutter 回环测试及源码检查不能代替 Windows 原生测试或真实磁盘性能验收。真实 Windows 上一万张 ARW 的启动耗时、目录操作响应、文件读取及跨设备传输仍需使用修复后的 Windows 构建核验。

发布前 Windows CI 暴露首次索引保存失败：完整路径改名需要重新以写权限打开目标父目录，与保护目录链的共享限制冲突。缓存提交改为保留临时文件的写入与删除句柄，刷新后通过系统 `NtSetInformationFile(FileRenameInformation)` 以单个目标文件名完成同目录原子替换，不按进程当前目录解析目标，不释放父目录保护，也不放宽其写入或删除共享。取消或提交失败通过原文件句柄清理临时文件，保留旧索引；错误保留数值诊断但不输出本机路径。同目录改名语义见 [Microsoft FILE_RENAME_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)。

回归明确检查扫描后的持久化警告、缓存文件存在性，以及独占锁前后两次恢复的各项元数据，并覆盖提交前的目录及临时文件保护、首写、替换、取消和失败清理。实际修复验证以 [1.0.1 发布记录](releases/1.0.1.md) 为准。
