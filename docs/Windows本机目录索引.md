# Windows 本机目录恢复与后台扫描

本页记录 v1.0.1 建立的持久目录索引，以及当前 `unstaged` 中的目录监听和可配置完整核对策略。以下「当前未发布策略」尚未包含在已发布安装包中；v1.0.1 的实际测试、打包与发布状态见 [1.0.1 发布记录](releases/1.0.1.md)。

## 当前未发布策略

Windows 本机共享目录的核对与接收其他设备的相册同步分开计时。设置中的「共享文件夹完整核对间隔」接受 **1–8760 的整数小时，默认 24 小时**；保存失败保留原值并提示重试。它只影响 Windows 来源端的完整目录核对，不改变「自动同步间隔」的分钟设置、原文件下载或其他平台的扫描规则。

| 场景 | 行为 |
| --- | --- |
| 启动或返回前台 | 优先恢复有效目录索引；共享目录配置匹配、没有未提交变化标记且上次成功完整核对尚未到期时，直接使用缓存，不因窗口重新获得焦点就全量扫描。每次实际读取原文件或缩略图仍核验目录和文件状态。 |
| 运行期间批量增删 | 使用 Windows 目录变化通知，将重复路径合并；事件安静 2 秒后处理，连续变化最长累计 10 秒即处理一批。只检查变动文件或目录子树，保留未受影响条目。 |
| 定期保底 | 从上次成功完整核对完成的时间加上用户设置的小时数判断到期。计时跨重启保留，成功的局部更新不推迟这个截止时间。修改设置会按同一次成功时间重新排期；缩短后已经到期则安排核对。 |
| 手动刷新 | 右上角刷新或桌面刷新快捷键立即请求完整核对，不受小时设置限制；同时沿用现有对端相册手动同步规则。 |
| 首次或异常兜底 | 没有有效索引、共享根配置改变、缓存不可用、通知缓冲溢出或事件无法安全解释时，执行完整扫描；失败不发布空目录或半完成快照，用户可见错误并可重试。 |

完整扫描继续遍历轻量文件元数据。局部检查的磁盘读取仅针对变动文件或子树，但发布时仍整理完整元数据快照、计算目录 revision，结果有变化才按现有格式保存索引；这不是新的增量 gRPC 协议。无媒体变化的事件不重写缓存，避免共享根包含应用缓存目录时形成写入与通知的反馈循环。图片内容不在扫描阶段解码，未修改条目的缩略图继续复用。

### 监听与生命周期

`LocalCatalogMaintenance` 先订阅 `tamayura/catalog`，再调用 `startWatchingDirectories`。网络启动不等待目录监听就绪：gRPC 先绑定端口，设备发现与设置操作可继续；`_PlatformMediaSource.restore/scan` 在后台等待监听准备完成，首轮原生通知读取挂起后才恢复缓存或扫描目录。慢速 HDD 唤醒不会把这段等待加入网络启动流程；扫描期间到达的事件继续排队。`catalog_watcher.cpp` 使用一个 IOCP 工作线程，递归监听共享根，并观察祖先目录中相关名称的变化。原生事件及 Dart 待处理集合均限制为 4096 条；溢出要求完整核对，不能静默忽略。

监听的启动和停止交给独立的单线程配置队列，逐级打开目录或唤醒 HDD 不占用平台 UI 线程，也不排在普通读写或预览解码队列中。平台线程先更新操作代次；过期排队请求直接失效，正在执行的旧启动完成后立即撤销，旧事件不再转发。启动方法的异步结果只在首轮读取已经挂起后返回，保持「先监听、后扫描」的顺序。

原生缓冲溢出后继续接收通知。根目录移走、监听错误或需要重新定位目录时，恢复核对前重新建立监听；无法监听会显示提示，并保留完整核对和手动刷新。扫描失败的自动重试带退避，避免对不可访问的磁盘连续空转。共享配置变更会更换监听代次；旧事件和迟到扫描不能覆盖新目录。共享根被移除后立即停止提供该目录文件。

停止网络共享、退出或更新关闭流程会撤销监听、计时器和在途扫描，取消的原生 I/O 完成后才释放通知缓冲及句柄。宿主析构时先使排队操作失效，等待配置线程退出后再停止监听，防止迟到启动恢复旧会话；退出仍可能等待当前系统调用结束。Windows 对持有开放后代句柄的目录移动存在限制；监听使用共享读、写、删除方式打开目录，但不能承诺任意祖先目录都能随时移动。停止共享会释放监听句柄，完成移动后需重新选择正确的共享目录。

没有引入 USN 变更日志、开机自启、后台系统服务或唤醒机制。程序退出、停止共享或系统未允许执行期间发生的增删，可能要到手动刷新或下次到期完整核对才被发现；新照片不保证下一次启动立即出现。完整核对依赖应用运行且允许共享，睡眠期间不保证按时执行。目录更新也不代表对端已同步；对端仍按其自己的相册同步间隔或手动刷新更新缓存。

计时器最多每小时重新判断一次到期时间，以处理系统时间和睡眠变化；这一步只比较保存的时间与当前配置，不代表每小时遍历媒体目录。

### 配置与兼容

- `localScanIntervalHours`：现有设置表中的整数小时字符串，范围 1–8760；缺失或无效时使用默认 24，不改写其他设置。
- `localCatalogFullScan`：现有设置表中的 JSON，`version: 1`，`completedMs` 为最近成功完整核对完成的毫秒时间戳，`roots` 为当次共享目录配置的 JSON 字符串，包含目录 ID、名称和本机 URI。停止或退出时若有已收到但尚未提交的变化，保存 `needsCheck: true`；下次启动即使原核对时间尚未到期也必须完整核对，成功完整核对后清除此标记。仅本机保存，不通过 gRPC 发送。
- 只有完整快照被服务层接受后才更新时间；恢复缓存、收到监听事件、局部更新及失败扫描都不能冒充成功完整核对。只有目录索引持久保存成功时才写入新的持久时间记录；时间记录保存失败会提示，下一次启动可能再次核对。
- 目录配置不匹配、没有有效成功时间或时间位于未来时，不据此跳过完整核对。未知记录版本保留原值并报告错误，当前进程不覆盖它；无效记录不作为缓存新鲜度依据。
- 媒体库 schema **7**、下载任务库 schema **3**、`catalog/local-catalog.bin` 格式 **1** 和 gRPC **v4** 均保持不变。新增配置采用兼容默认值，保留既有共享目录、设备、离线相册、下载历史和未完成任务；异常缓存的保留规则见下文。

回归入口包括 `test/local_catalog_maintenance_test.dart`、Windows 启动及桥接测试、设置界面测试，以及 `windows/tests/catalog_watcher_test.cpp`、`partial_catalog_test.cpp`。它们覆盖间隔保存与重启、到期排期、批量合并、扫描中事件、局部增删、通知丢失、失败和取消边界；不把下文历史验证数量或自动化行为覆盖当作本轮真实 HDD 性能验收。

## v1.0.1 启动与界面基线

Windows 启动先恢复设置及对端离线相册，再开启 gRPC 与 mDNS / DNS-SD。共享目录的本机索引在后台恢复并核对，不再把整个扫描包含在界面的全局忙状态中。设备在线核验、手动连接、设置及目录增删可以继续工作；共享目录区显示独立的检查状态。

此前每次启动都会在监听 gRPC 之前完整扫描共享目录，本机索引又仅保存在进程内，因此重启后的扫描期间不能供对端下载，设备发现尚未启动，目录操作也会一直禁用。新流程将网络可达、目录可用和扫描进行中分开处理。

首次运行修复版本没有本机索引缓存，仍需完成一次扫描才能共享媒体。此时身份请求可用，但目录和文件请求明确返回暂不可用，不把未完成扫描当作空目录，不让对端误删离线相册。之后启动从缓存恢复完整目录，对端可以在后台核对期间继续下载；每次读取仍检查文件状态及目录访问权限。

v1.0.1 每次启动仍完整遍历轻量文件元数据，以发现应用退出期间的增删；该版本没有引入文件监控或 USN 增量日志。ARW 只在此阶段读取文件名、大小、修改时间等信息，不解码原图、生成全库缩略图或哈希原文件内容。扫描复用已固定的父目录句柄，避免为每个文件重复打开整条目录链。当前未发布源码的触发规则见上文。

## 索引缓存与数据保留

本机索引单独保存在应用数据目录内的 `catalog/local-catalog.bin`，格式版本为 1，不改动媒体库 schema 7、下载任务库 schema 3、现有设置及 gRPC v4。索引限制为 512 MiB、100 万条，超限提示缓存不可用而继续提供当前完整扫描结果；未来格式变更须提供迁移或保留原文件并安全拒绝。

- 缓存包含版本、共享目录配置和媒体轻量元数据；不保存缩略图或原文件内容。只有共享根配置完全匹配时才能恢复为完整目录。
- 恢复核验共享根可访问，并从当前共享根和经过校验的相对路径重新构造文件位置。缓存中的索引不能绕过路径、重解析点、大小及修改时间检查；已删除或变化的文件仍拒绝按旧信息下载。
- 完整扫描成功后原子替换索引缓存；写入失败会提示，但不会撤销已经扫描成功的共享目录。扫描失败或被取消不能把未完成结果发布为正式目录。
- 损坏或较新版本的缓存保留原文件并报告错误，当前进程停止覆盖该缓存，继续通过完整扫描提供共享。不会清空原有数据库、下载分片或用户媒体。

## 并发与撤销

普通重扫保留上次完整目录，新结果经校验、排序、目录摘要计算后整体发布。Dart 的大目录整理在独立 isolate 中执行，平台结果到模型的转换分批让出执行权；跨平台协议的排序及 revision 算法保持一致。

扫描与恢复都有代次校验。共享目录变更立即淘汰旧任务，被移除的目录停止提供文件；仍共享目录中的旧文件继续可读。新目录配置尚未完整扫描时，目录分页暂不可用，避免发布不完整的组合快照。停止共享或退出时撤销正在恢复、扫描的任务，迟到结果不能重启监听或覆盖新状态；停止共享不会删除持久索引。

Android 的后台共享就绪握手保持原来的完整扫描要求；本次仅 Windows 启用提前监听、后台恢复模式。其他平台沿用原有启动流程，公共目录摘要处理与协议行为有回归覆盖。

自动化覆盖慢启动、无缓存与恢复缓存、万张 ARW 规模的轻量元数据、扫描期间 gRPC 下载和设备发现、目录增删、生命周期取消、权限失败与缓存异常。Windows 原生测试覆盖持久索引、安全恢复、版本保护、原子替换及取消边界。

2026-10-28 开发阶段在规定的 Flutter 3.47.6 / Dart 3.13.5 环境完成格式检查、静态分析和全量 Flutter 测试（1076 项，含覆盖率），Windows 源码交接检查 7 项通过。新增 Windows 原生索引测试 12 项已注册到 CTest；该次开发检查没有 Windows 编译运行环境，未执行这些原生测试或构建 Windows 安装包。上述结果不代替 v1.0.1 发布提交的完整检查，本次发布结果统一记录在 [1.0.1 发布记录](releases/1.0.1.md)。

平台通道仍一次传回完整轻量元数据，编解码大消息可能出现短时卡帧；本次解除启动依赖并移出大目录排序与摘要工作，不承诺未经实机测量的帧率或启动耗时。

本机运行的 Flutter 回环测试及源码检查不能代替 Windows 原生测试或真实磁盘性能验收。真实 Windows 上一万张 ARW 的启动耗时、目录操作响应、文件读取及跨设备传输仍需使用修复后的 Windows 构建核验。

发布前 Windows CI 暴露首次索引保存失败：完整路径改名需要重新以写权限打开目标父目录，与保护目录链的共享限制冲突。缓存提交改为保留临时文件的写入与删除句柄，刷新后通过系统 `NtSetInformationFile(FileRenameInformation)` 以单个目标文件名完成同目录原子替换，不按进程当前目录解析目标，不释放父目录保护，也不放宽其写入或删除共享。取消或提交失败通过原文件句柄清理临时文件，保留旧索引；错误保留数值诊断但不输出本机路径。同目录改名语义见 [Microsoft FILE_RENAME_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)。

回归明确检查扫描后的持久化警告、缓存文件存在性，以及独占锁前后两次恢复的各项元数据，并覆盖提交前的目录及临时文件保护、首写、替换、取消和失败清理。实际修复验证以 [1.0.1 发布记录](releases/1.0.1.md) 为准。
