# Windows 稳定性检查

本文记录 `CHANGELOG.md` 中 `unstaged` 的 Windows 稳定性修复，不代表已发布的安装包已包含这些改动。沿用 Flutter 3.47.6 / Dart 3.13.5、媒体库 schema 7、下载任务库 schema 3、配置格式和 gRPC v4，不清空或迁移用户数据。

## 已定位的路径

### 设备发现的锁与回调

Windows DNS-SD 的启动、取消和注销可能与异步完成回调交错。原实现部分系统调用持有会话或注册锁，而回调也需要这些锁；系统调用等待回调时可形成锁等待环，窗口线程参与停止发现时也会受影响。

`LanDiscovery` 现在在锁内仅更新状态和取得操作引用，锁外调用 DNS API。启动尚未返回时的取消会推迟到取得有效取消句柄之后；早到完成、迟到最终回调仍由独立操作对象维持生命周期。停止会话立即禁止旧事件发送，最终回调到来后释放操作的自持有引用。解析前在锁内重新检查退避时间，防止同批重复 PTR 或并发广播绕过解析间隔。

`dns_service_api.h` 提供原生测试注入点，生产默认仍使用系统 DNS-SD，不引入替代发现协议。

### 消息循环与工作线程

原生回包过去每条都向窗口投递消息，一次又处理整批积压任务。现在 `UiDispatcher` 合并唤醒，每批最多处理 32 条，后续批次通过低优先级定时器让输入与绘制有机会运行。Windows 消息队列临时满时保留待回复任务，由既有维护定时器恢复处理；窗口销毁后不再回复已经失效的通道。

WIC 和 Shell 预览使用两个独立工作线程；目录扫描、原文件读取、保存等工作使用 2–8 个线程（硬件数量未知时为 4）。因此慢预览不会占满传输与目录操作的工作队列。普通工作线程上限也避免高核心数机器创建过多本机工作线程。

这不是强制终止第三方解码器的机制。系统/第三方 Shell 或 WIC 调用若永不返回，预览仍可能等待，真正退出时也仍等待正在执行的原生操作。不使用 `TerminateThread` 或分离持有文件的线程，以免破坏保存操作与对象生命周期。

### 大图与目录索引

普通图片和 RAW 完整帧回退统一使用“按存储方向缩小 → 24 位 BGR 物化 → EXIF 旋转/镜像 → JPEG 编码”的路径。旋转器访问的是小位图，避免按列或逆序访问惰性解码源时反复解码。256 像素缩略图最多约 192 KiB，最大 2560 像素预览最多约 18.75 MiB 物化像素；该限制不包括解码器自身内存。

目录 Scan/Restore 发布通过交换映射完成，旧索引在锁外析构；原子缓存提交仍与代次检查一起保护，保留撤销共享后迟到扫描不能重新发布或落盘的约束。

### 空闲界面开销

下载任务轮询继续按原间隔执行，但只在任务增删、状态、进度、错误或媒体信息变化时通知界面。未变化时保留现有视图与缩略图对象，减少整个应用每秒重建的开销。此项降低持续开销，不能单独认定为偶发原生卡死的根因。

## 回归覆盖

归档检查发现直接从个人检出目录构建时，Flutter AOT 会在 `data/app.so` 中保留源文件 URI。Windows 打包改在中性临时源码副本中执行检查和构建，归档前再扫描路径标记；测试专用清单仍不得进入发行目录。这不影响普通 `flutter run` 调试，分发使用打包脚本的完整 ZIP。

更新原生测试还复现了辅助进程准备失败：`.MainModule` 在进程模块枚举不可用时返回空值，错误对话框又阻止辅助进程退出，最终被误报为启动超时。更新脚本改用 `QueryFullProcessImageNameW` 读取已持有进程句柄的映像路径；准备失败立即转交脱敏错误，不显示阻塞对话框。仍验证父进程确为目标应用，错误父进程测试确认旧包未移动或替换。

- `lan_discovery_test.cpp`：跨线程早到完成、取消/注销等待回调、启动中取消、goodbye、停止后迟到最终回调、重复启停与资源释放、重复 PTR 退避。
- `windows_executor_test.cpp`：通知合并、分批处理与输入机会、销毁时迟到任务、慢预览与普通 I/O 隔离及停止队列。
- 执行器还覆盖响应回调重入销毁所有者、线程创建部分失败后的回收；维护回调在派发之后不再访问所有者，构造失败保留原异常并回收已经启动的线程。
- `preview_test.cpp`：普通图片与 RAW 完整帧回退、三种尺寸、八种 EXIF 方向共 48 个组合，检查按存储方向顺序读取像素及资源/I/O 错误传播。原始存储实现配合新增测试在 Windows WIC 下失败，修复实现通过。
- `transfer_polling_test.dart`：空闲与静止任务不通知，状态/进度、媒体元数据、缩略图及任务移除仍更新。
- 既有存储、目录缓存、缩略图缓存、托盘、单实例、更新与 Flutter 业务/界面测试继续保留。

## 本机验证范围

2026-11-14 在 Windows 11 x64 上执行本轮检查。已用微软调试工具观察长期运行的既有安装包：采样时主窗口线程处于消息等待，页面点击可以响应；大量等待线程位于 Windows 系统线程池，不能仅据线程数量认定是应用死锁或本轮代码已经修复的泄漏。转储与原始环境信息只保留在本机临时目录，不纳入源码或分发包。

Windows Application 事件日志中有 1.0.0 与 1.0.1 的两次 Application Hang 记录，但对应错误报告目录未留下可分析转储，事件本身也未给出确定的挂起类型。因此本轮可确认历史无响应发生过，并通过回归复现和修复具体风险路径，不能把历史两次挂起直接归因到某个已修复函数。

本轮已执行格式检查（130 个 Dart 文件无变化）、Flutter 静态分析、全部 1077 项 Flutter 测试和覆盖率生成；Windows 原生 CTest 11/11 通过，包含 DNS 生命周期 7 组、执行器最终 6 组及更新脚本 15 组用例。Windows 源码交接检查运行 9 项，其中 8 项通过，1 项因当前用户不能创建符号链接而跳过；新 junction 拒绝用例实际通过。打包辅助脚本 7 项回归通过，覆盖源码筛选、中性路径、清理边界、插件 junction 恢复以及跨读取块的多种路径编码隐私检查。完整中性目录打包重新执行公共检查、全部 Flutter 测试和原生 CTest，均通过，并完成 Windows x64 Release 编译。

修复构建在本机读取原有相册与设置，页面点击、最大化、关闭到托盘及重复启动恢复同一进程与页面已验证。只读回环 gRPC 冒烟覆盖 8139 条实际本机目录元数据中的首个分页、24 张缩略图和 100 次连续身份请求；身份请求 p95 为 7 ms、最大 25 ms。这不是跨设备传输测试，也不是与旧版同负载的性能对照。快捷键自动化投递未确认成功，未将其记为通过。

进一步负载检查完成 8139 条目录的全部分页、64 张分散缩略图，以及一个大于 50 MiB 原文件的四路 8 MiB 范围读取；总计 32 MiB 的并发结果与随后串行读取的 SHA-256 一致。独立进程、独立连接的轻量心跳与负载并行运行，600 次身份请求全部成功，p95 为 8 ms、最大 363 ms，客户端定时器最大额外调度延迟 42 ms。共用 isolate 和连接的混合探针曾出现 12.7 秒长尾，混入了客户端哈希、protobuf 处理和单连接排队，不能直接作为服务端挂起证据。检查期间还有本机构建负载，上述数值只描述本轮运行，不是受控性能基准。

最终本地 ZIP 含 31 个文件，独立核对 ZIP 完整性、SHA-256、更新清单逐文件大小与哈希，并扫描 UTF-8/UTF-16 路径，未发现原检出目录或个人目录。旧程序完整保留后，在原便携版路径安装此未发布、未签名测试构建，版本仍为 `1.0.1+17`，未创建 Tag 或 GitHub Release。两个数据库已备份并通过完整性检查，schema 仍为 7 和 3；安装未清空数据。最终安装版正常显示原有相册，只有一个进程，SQLite 与 Flutter 引擎均从安装目录加载；100 次只读身份请求与 24 张缩略图冒烟通过，身份请求 p95 为 3 ms、最大 22 ms。中性临时构建工作区已清理。

真实 Wi-Fi 跨设备互传、系统睡眠恢复、第三方编解码器组合及长时间运行仍需分别验证，短时 GUI 检查和原生回归不能替代这些场景。

## 再次出现无响应时

在终止进程前记录发生时的操作、是否正在扫描/预览/下载、是否刚从睡眠或托盘恢复，并区分整个窗口无响应与某个请求一直等待。使用微软调试工具把转储保存到系统临时目录，再离线查看主线程和工作线程栈；运行中的采样应限时结束并及时分离调试器。转储可能包含设备与媒体数据，不提交到仓库、不放入发行 ZIP。

只记录脱敏结果：主线程是否卡在锁或系统调用、预览线程是否停在 WIC/Shell、任务队列是否持续增长。大量 `ntdll!TppWorkerThread` 等待线程本身不等于死锁，需要结合活动回调和主线程栈判断。有关工具与线程池命令见微软 [Debugging Tools for Windows](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/debugger-download-tools) 和 [!tp](https://learn.microsoft.com/en-us/windows-hardware/drivers/debuggercmds/-tp)。
