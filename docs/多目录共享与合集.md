# 多目录共享与合集

本功能随 **0.0.2 本地签名试用版**交付；安装包与发布验证记录见 [0.0.2 试用版本说明](releases/0.0.2.md)。两端都需要更新到协议 v3，旧数据库直接清空重建，需要重新选择目录；外部文件保留。

## 使用方式

在设置的「共享文件夹」中逐个添加目录，也可以移除单个目录。选中的每个目录都会递归扫描图片和视频；选父目录后无需再选子目录。完全相同、先父后子、先子后父都拒绝添加，原有列表保持不变。同级目录以及名称相同但位置不同的目录可以同时共享。

接收文件的结构为：

```text
接收目录/
  小张的手机/
    DCIM/
      Camera/2026/照片.jpg
      Screenshots/截图.png
    Pictures/
      旅行/秋天/照片.jpg
```

相册首页显示「DCIM」「Pictures」两个合集，每个合集显示对端设备、封面和媒体总数。进入 DCIM 后直接浏览所有子目录中的照片，不需要逐级进入 Camera、2026。相册按共享目录标识分组，名称相同的不同共享根、不同设备之间不会合并；点照片仍然是下载原文件，合集本身不自动批量下载。

## 共享配置与扫描

- `settings.sharedFolders` 保存 JSON 数组，每项为 `{id, uri, name}`。`id` 在添加时生成 UUID，后续刷新与重启保留；URI 仅保留在本机。
- `validateSharedDirectory` 在写配置前检查授权和重叠；原生再次检查整个集合后扫描，防止配置绕过验证。使用文档提供者的父子关系查询，并为 Android 外部存储的卷与文档路径提供边界明确的判断。
- 目录关系无法确认时返回 `DIR_RELATION_UNKNOWN`，已确认重叠返回 `DIR_OVERLAP`。不同提供者可能映射同一物理目录，当前无法证明独立时也会拒绝添加。
- `scanDirectoriesMetadata` 一次接收全部共享目录。每个文件保存所属授权树、共享目录标识和从根开始的相对路径（包含文件名），媒体 ID 为共享目录 ID 与文档 ID 的 SHA-256。
- 扫描开始撤销旧映射，所有目录完整成功后才发布整个快照。任何一个共享目录丢失权限、根目录无法读取或扫描期间消失都使本次快照不可用，接收端保留上次完整缓存。可移除失效目录后重新刷新。目录内单个文件或子目录无法读取、名称不合规时只跳过该项；Dart 服务端也跳过无效条目以及 ID 或「共享目录 + 相对路径」重复的条目。清空共享列表则发布合法空快照，供对端同步删除索引。
- 读取文件与缩略图继续检查该文件所属树的授权和扫描代数；移除目录后旧文件不能继续通过旧映射读取。移除共享目录不删除任何源文件或已下载副本。

## 协议、缓存与合集

gRPC 当前协议版本为 **4**（读取窗口限制，见 [传输恢复](传输恢复.md)）；`MediaEntry` 自 v3 起包含 `shared_folder_id`、`shared_folder_name`、`relative_path`。字段参与元数据相等比较，传入存储和协议边界时验证相对路径：拒绝绝对路径、空段、`.`、`..`、反斜杠、控制字符以及末段与文件名不一致的数据。

目录快照暂存表和正式媒体表均保存三个字段。`mediaCollections` 从完整缓存按设备 ID 和共享目录 ID 聚合数量，并读取每组一张封面，合集不会受已加载的照片页数限制。没有媒体的目录不生成空合集。进入合集后 `listMediaPage` 同时按设备与共享根过滤，仍使用 60 项游标页；切换合集或设备使旧异步分页失效。同步删掉整个合集时自动返回合集列表。

SQLite 媒体库 schema 为 3、下载任务库为 2。遵循 v1.0.0 前只维护最新结构的约定，旧库直接清空重建，不提供旧配置转换或数据迁移。覆盖安装后需重新选择共享与接收目录、发现设备；两端均需更新到当前协议。外部文件不受数据库重建影响。

## 层级接收和重名

入队时持久化媒体位置和实际目标目录段，后台 worker 重启后无需依赖前台状态。`destination_directories` 在事务中维护「接收根 + 上级身份 + 当前身份」到目录名的映射：

1. 优先使用对端设备名与共享目录原名；后续同名项追加 ` (2)`、` (3)`。
2. 大小写差异及非法字符替换造成的同名也区分；同名共享目录根据各自 ID 独立分配。
3. 对每层子目录采用相同规则，保留层数。合法常见名称原样保留；控制字符、Windows 不可用字符、保留名、过长名称转换为可保存的名称。
4. 映射持久化后不因设备改名、下载重试或进程重启改变，避免同一来源散落到多处。更换接收根时独立分配。

`saveDownload` 接收目标目录段列表，通过 SAF 从接收树逐级查询、创建或复用目录。原生进程级锁保护目录创建与目标文件分配，多个后台引擎不会同时创建相同目录；实际文件复制仍可并行。同名文件另存而不覆盖已有文档，失败或取消时清理当前未完成文档。中间目录创建失败、目录授权撤销或存储空间不足都会作为可重试的下载错误返回，已接收分片保留。

## 验证

自动化覆盖多根配置、重叠拒绝后的状态保留、递归相对路径传输、目录独立移除、协议非法路径、离线合集聚合、同名合集隔离、合集分页、后台任务重启和接收目录名称冲突。原生 JVM 测试覆盖多树共享映射、扫描代数、父子边界、路径段和重名分配。

开发阶段已通过 130 项 Flutter 测试、项目 28 项 Kotlin JVM 测试、Dart 格式和静态检查，并构建调试 APK。0.0.2 的独立发布检查、release 包验签与产物校验记录见 [版本说明](releases/0.0.2.md)；既有 `dist/0.0.1` 试用 APK 不包含本功能。

真机验收仍需两台 Android 16+ 设备：添加两个含同名文件的共享根，分别测试父子选择顺序；下载根目录文件与多层子目录文件，核对接收结构和内容；验证两个同名设备、两个同名共享根不会混合；撤销一个共享根授权后确认对端缓存保留，移除该根后确认其余共享恢复；在后台并行下载同一子目录文件，检查不会产生多份父目录。
