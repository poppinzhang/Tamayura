# Windows RAW 预览与来源端缩略图缓存

本文对应 `CHANGELOG.md` 的 `0.7.0`，该版本正在准备发布，尚未包含在已发布的 0.6.1 安装包中；本版发布验证状态见 [0.7.0 发布记录](releases/0.7.0.md)。修改仅涉及 Windows 原生媒体来源；gRPC 协议、接收端 SQLite 缓存和同步分页保持现有格式，不需要清空数据库。

## RAW 预览选择

Windows 通过 WIC 为 DNG、CR2、NEF、ARW 生成预览。原实现直接缩放完整图像帧，RAW 解码器可能需要处理数千万像素，最终却只传输一张最长边 256 像素的 JPEG。目录元数据请求很快时，首次相册同步仍可能受这一 CPU 开销限制。

`JpegPreview` 识别 RAW 后，由 `WicJpegPreview` 依次尝试解码器缩略图、帧缩略图、解码器预览。候选图像的尺寸必须有效，最长边不小于请求尺寸；必须完整完成缩放和 JPEG 编码，才算可用。接口不支持、尺寸不足或候选图像解码失败时继续尝试，全部不可用才读取完整帧像素。读取完整帧的尺寸或方向元数据不等于解码其像素。

内嵌图像先按存储方向等比缩小，转换为 24 位 BGR 并一次性读取到小位图，再进行方向变换与 JPEG 编码。这样可以避免旋转器按列访问惰性 RAW 解码源、反复解码内嵌图像。临时位图只保留缩小后的像素；在当前 256 像素请求下最多约 192 KiB，在接口允许的最大 2560 像素请求下最多约 18.75 MiB，不复制完整尺寸预览。

缩略图保留候选预览的宽高比例及相机内嵌裁切，不为匹配 RAW 传感器尺寸拉伸图像。RAW 主图存在有效方向信息时，以主图方向为准并只应用一次；主图未提供方向时才使用内嵌图像自身的方向。某些相机的嵌入 JPEG 标记为方向 1，但像素仍处于 RAW 原始方向，不能因此跳过主图要求的旋转。普通图片仍使用现有完整帧流程，视频与 WIC 不支持的格式继续由系统 Shell 提供预览。系统没有相应 RAW 解码器时不保证可以生成预览。

可选内嵌预览不支持、内容损坏或尺寸不足不会终止整个相册同步。完整帧及系统预览仍不可解码时，保持[单张缩略图容错](单张缩略图容错.md)的空图语义；WIC 内存不足、权限、文件读取和流错误分别保留为资源、权限或 I/O 错误，不尝试以空图替代，也不进入缓存，恢复后可以重试。

## 来源端缓存

Windows 的 `MediaCatalog` 为生成结果维护进程内 LRU 缓存，默认最多 **32 MiB JPEG 字节、4096 条记录**，两项限制同时生效。命中会更新最近使用顺序，满额时淘汰最久未使用的条目；空预览也占一条记录，避免无可用解码器的文件被反复尝试。超过 gRPC 单张上限 **512 KiB** 的结果不进入缓存，仍交给现有 RPC 上限规则处理。

缓存按媒体 ID 与发布时的实际文件路径、共享根、大小、修改时间匹配。每次请求，包括缓存命中和等待同一生成任务的请求，都先固定共享根及文件句柄，检查可访问性和扫描时的文件状态。因此：

- 文件缺失或已变化时不能继续返回旧预览；共享根不可用、权限不足、共享冲突和 I/O 错误仍可见。
- 同一文件的并发请求合用一次生成结果，生成失败会唤醒等待者；可恢复错误不缓存，下次可以重试。
- 成功重扫保留元数据未变的条目，删除或变更条目立即淘汰；开始扫描时先移除已取消共享目录的条目。
- 清空共享目录或当前扫描失败时清除缓存，并使在途生成结果失效；迟到任务不能重新填回旧结果。仅暂停网络共享时不额外清空缓存，恢复后的扫描和每次请求仍重新检查来源状态。

缓存仅保存缩略图，不保存原文件，不写磁盘。退出进程后消失；不同进程不共享。32 MiB 限制只计已保留的图像字节，缓存索引、在途解码器内存和返回结果副本不包含在该数字内。接收端的离线 SQLite 缩略图仍独立保存，详见[缩略图存储](缩略图存储.md)。

## 验证方式与范围

`windows/tests/preview_test.cpp` 使用合成图像和可控 WIC 接口验证内嵌预览优先、候选失败回退、完整帧像素不被提前读取、方向和输出尺寸；惰性源用例统计访问区域，验证按存储方向顺序读取且每个像素只读一次，覆盖横图、旋转和镜像，防止重复或按列解码的性能回归。WIC 缩放器可以分多行调用 `CopyPixels`，不能把接口调用次数直接当作重复解码次数。测试无需安装可选 RAW 解码器或提交私人相片。

`windows/tests/thumbnail_cache_test.cpp` 验证重复与并发请求复用、容量和 LRU 淘汰、空图、失败重试、重扫复用、文件与目录失效、撤销共享及迟到结果。既有 `storage_test.cpp` 继续覆盖真实 WIC 编码、EXIF 方向、文件系统权限和严格范围读取。

从项目根目录运行 `scripts/test-windows-native.ps1` 执行全部 Windows 原生测试。真实 RAW 的性能可在 Windows 本机比较同一文件的完整帧、内嵌预览、首次缓存读取和再次命中的耗时，只记录脱敏尺寸及耗时，不复制媒体、不提交本机目录和连接信息。原生测试或本机计时不能代替正常应用 GUI 和跨设备相册同步验收。

本轮在 Windows x64 上使用两张真实 ARW 分别验证横图与竖图。原文件只在来源机器读取，测量结果如下；这是单张生成路径对照，不代表整个相册同步的固定提速比例。

| 样本 | 完整帧生成 | 内嵌预览首次生成 | 缓存命中 | 未变目录重扫后命中 |
| --- | --- | --- | --- | --- |
| 横图，输出 256 × 144 | 4459 ms | 438 ms | 1.12 ms | 1.01 ms |
| 竖图，输出 144 × 256 | 4949 ms | 249 ms | 1.06 ms | 1.08 ms |

两张样本的首次请求、再次请求及重扫后请求均返回相同 JPEG 字节，每张仅调用一次生成器。竖图同时验证了 RAW 主图方向与内嵌 JPEG 方向冲突的处理。

本修复的独立源码快照已通过格式检查、Flutter 静态分析及 731 项 Flutter 测试、4 项 Windows 源码检查、全部 5 项 Windows 原生 CTest 和 Windows x64 Release 编译。新增原生用例包括 14 组预览测试和 13 组缓存测试；移除旋转前小图物化的临时对照实现会在顺序像素读取断言处失败。托盘测试在已登录的交互桌面会话执行。以上结果仅覆盖本修复快照，不表示工作区其它并行改动已验证，也不表示已替换运行中的安装包或完成跨设备 GUI 验收。
