## 本版变更

完整说明见 [CHANGELOG 0.8.0](../../CHANGELOG.md#080)，Release 正文使用 Tag 内该版本段落。

- 新增「设置 → 检查更新」：读取实际安装版本，查询 GitHub Releases，包含预发布并排除草稿；发现新版本先征求用户确认，拒绝后不下载、安装或打开浏览器。
- Android 确认后下载对应 APK，校验完整性及应用身份、版本、签名，自动发起系统安装；首次可能需要允许安装此来源，并由用户完成系统确认。拒绝、授权不足、签名冲突和安装失败可以显示错误并重试，不承诺静默安装。
- Windows 确认后下载对应 x64 ZIP，校验完整目录清单并准备新目录，退出应用后替换整个目录并重新启动。准备失败保留运行中的原程序；替换失败尝试恢复旧程序。该能力用于可写独立目录中的完整发行包，不新增独立安装器、MSIX 或自动提权。
- macOS 确认后仅打开对应版本的 GitHub Release 页面，下载和替换 App 由用户手动完成。
- 下载显示进度并允许取消；校验失败、网络中断、限流及附件不完整均明确提示。更新只在用户主动操作时检查，不新增启动轮询、强制更新或差分包。实现与边界见 [应用更新](../应用更新.md)。
- Windows 更新与打包脚本显式加载 ZIP 压缩程序集；更新脚本从当前 PowerShell 安装目录加载内置模块，避免继承其他 PowerShell 版本的模块路径后无法使用文件哈希、JSON 或进程命令。

## 失败与重试记录

发布准备期间有两次 Windows 分支 CI 失败，均在打 Tag 前修复：

1. 初始提交 `663886d03004aaeb28438e0199dec001a0894139` 的 PowerShell 5.1 未加载 ZIP 压缩类型，更新回归在创建 ZIP 时失败。后续提交显式加载压缩程序集。
2. 提交 `0db78e2191e5c8c564895999abbfa8a0bdc6492b` 仍受继承的其他 PowerShell 版本模块路径影响，内置命令加载失败。最终提交改为从当前 `$PSHOME` 加载 Management / Utility 模块，并增加进程内及辅助进程在受污染模块路径下的回归。

每次改动后均回到发布前验证步骤；最终提交重新完成本地 Android / macOS 全量检查、打包与核验，三平台分支 CI 全部成功后才创建 `v0.8.0`，没有给前两个失败提交打版本 Tag。

Tag 首轮 Windows 的 14 个更新流程用例全部通过，随后测试的最终根目录清理与辅助进程退出发生竞争，导致 Windows job 失败；此时 prepare、Android、macOS 已成功，发布尚未完成。保留同一源码及 Tag，仅安全重跑失败的 Windows 与依赖的 publish，attempt 2 全部成功后才公开 Release。未通过修改已发布源码、移动 Tag 或跳过测试处理这次失败。

上述清理竞争不代表程序替换或重启失败；但辅助进程在退出前可能无法移除作为自身当前工作目录的空 GUID 缓存目录。**重试没有修复该测试时序问题。** 本版保留这一限制，未为重试改动 Tag 内实现；后续需让辅助进程先离开其当前工作目录，并让测试等待辅助进程完全退出后再清理测试根目录。

## 安装与数据

**0.7.0 没有检查更新功能，首次安装 0.8.0 必须手动完成。** 安装 0.8.0 后才可使用应用内入口检查后续版本。互联设备应使用同一版本。

Android 沿用 0.6.1 起的专用 release 证书和现有 Actions Secrets，本轮验签通过，同签名 release 包可覆盖安装；0.5.0 及更早旧签名包、debug 包不能直接覆盖。签名冲突时更新功能只报告错误，不自动卸载。用户自行卸载会清除设置、SAF 目录授权、缓存、下载记录、任务与未完成分片，需要重新选择目录并连接设备。

Windows 首次将完整发行 ZIP 解压至独立空目录后运行。后续自动更新要求应用目录及父目录可写、完整文件清单有效、目录中没有个人文件或链接；不能只保留 EXE，也不自动请求管理员权限。受保护目录、系统 PowerShell 策略或文件占用可能阻止更新，需按提示处理或手动升级。程序目录回滚不等于跨版本数据库回滚，也不表示新程序已通过完整启动健康检查。

macOS 完整解压并手动替换 `Tamayura.app`。当前仍为 ad-hoc 签名且未公证，被系统拦截时应确认来源与校验结果，再使用系统“隐私与安全性”提供的确认方式，不关闭全局 Gatekeeper。

本版保持协议 **v4**、媒体库 **schema 7**、独立下载任务库 **schema 3**，不因加入更新功能而主动清空这些数据库；自动同步继续使用分钟配置。v1.0.0 前仍不保证历史数据或跨版本兼容，不增加迁移和旧协议适配。升级会中断共享和传输，重新打开应用后可按既有机制重试中断任务，不承诺自动无缝续传。外部共享目录中的原媒体及已保存接收文件保留。

## 已知限制与验收边界

- 本版仍为试用性质的 Pre-release；macOS 未公证、Windows 未签名，不是应用商店发行。SHA-256 证明下载完整性，不能描述成 Windows 的独立发布者签名。
- Windows 成功更新会清理下载 ZIP 与辅助程序自有文件，但可能留下空 GUID 缓存目录；这不影响程序替换、重启或用户媒体。测试最终目录清理存在上述时序竞争，不能将首次 Tag 运行记为全成功。
- 更新查询及安装包下载需要互联网，走 GitHub HTTPS；媒体同步仍限可信 IPv4 局域网，继续使用无账号、鉴权或 TLS 的 gRPC 通信。
- Android 来源授权、系统安装确认、厂商限制与真实覆盖安装，Windows 文件占用、权限、退出重启及故障恢复，macOS 默认浏览器与手动替换均需真机验收。
- 三平台自动发现、目录授权、原文件传输、断网及睡眠恢复、后台共享、菜单、扫码与分享仍须按各平台实际能力验证；自动化不能替代。Sequoia / Intel、Windows 10 1809 与无开发工具用户机尚不能据测试代码存在而认定通过。
- Windows 仍仅支持 x64，无相机扫码或系统分享面板。后台共享受系统电源策略约束；更新不增加后台系统服务、开机自启或远程唤醒。
