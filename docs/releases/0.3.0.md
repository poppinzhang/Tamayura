日期：**2026-10-10**。

## 本版功能与修复

- **相册持久断点**：元数据整页与下一分页位置在同一数据库事务中保存，缩略图逐张落盘。中断后已经出现的照片和合集仍可浏览，重启后恢复计数与「继续同步」入口。
- **来源重启仍可恢复**：目录版本由稳定元数据摘要生成。相同目录在双方重启后仍可继续缺失缩略图及后续页；目录增删时重新核对分页元数据，复用匹配缩略图，完整快照成功后才应用删除。
- **修复重试从头开始**：普通网络和来源错误不再删除整个未完成快照。同步会话隔离旧请求，避免迟到写入、提交或自动重试覆盖新任务；手动连接与自动发现对同一设备的请求合并处理。
- **macOS 版本**：提供桌面侧栏、适应窗口尺寸的布局、系统目录选择与持久授权、递归媒体扫描、Bonjour 发现、预览、默认应用打开和系统分享；共用相册、合集、主题、设备记忆、gRPC v3 与下载逻辑。
- **原文件续传继续保留**：点击照片或视频才下载原文件，超过 50 MiB 使用四路 gRPC 范围流。Android 使用系统后台传输任务；Mac 在应用运行且系统清醒时接收，退出后可以重试并复用已保存分片。

完整变更见 [CHANGELOG](../../CHANGELOG.md)，实施与验证清单见 [同步进度与断点恢复](../同步进度.md) 和 [macOS 实现](../macOS原型.md)。相册同步进度统计元数据和缩略图，不表示原文件已经下载。

## 安装与升级

**双方设备应安装相同的 0.3.0 版本。本次媒体库 schema 升至 4，会清空重建旧缓存和设置，需要重新选择共享与接收目录、发现设备。** 这是 v1.0.0 前约定的直接重建，不提供旧数据迁移。外部共享照片与已经保存到接收目录的文件保留；本次更新之后建立的相册断点可跨中断和重启恢复。协议仍为 v3，下载任务库仍为 schema 2。

Android 同签名 release 版可覆盖安装：

```sh
adb install -r dist/0.3.0/Tamayura-0.3.0-android.apk
```

首次安装可去掉 `-r`，也可以通过文件管理器打开 APK。若此前安装的是 debug 签名版本，需先卸载。卸载会清除应用设置、目录授权、已记住的设备、离线缓存、下载记录和未完成分片；外部共享与接收文件保留。

macOS 解压 ZIP，将 `Tamayura.app` 放入「应用程序」后打开。该本地包未公证，系统可能阻止首次打开；确认来源和校验结果后，可在系统「隐私与安全性」页面确认打开，无需修改全局 Gatekeeper 设置。允许本地网络访问后，在应用设置中添加共享目录并选择接收目录；Mac 不直接读取 Apple「照片」图库，需要先导出媒体到普通文件夹。

双方处于同一局域网时，可通过自动发现、手动 IP 或二维码连接。相册出现中断提示后，恢复网络并选择「继续同步」或刷新；重新打开应用和自动发现也会尝试连接已记住的设备。Android 来源端需要锁屏共享时先开启「后台共享」；Mac 来源端需要保持应用运行和系统清醒。

## 已知限制与待验收

- Android 最低 API 36，macOS 最低 15.0。Sequoia 与 Intel 实机尚待验收；Universal 架构核验不等于已在两类硬件与所有系统版本上运行验证。
- Android 后台共享受系统 Doze、电池优化及厂商电源策略影响。Mac 共享和下载依赖应用运行与系统清醒；关闭最后一个窗口会退出，最小化不会退出。不提供后台守护进程、开机自启、防睡眠或局域网远程唤醒。
- 本次不新增自动定时重试。尚未写入数据库的单张缩略图需重新请求，清除应用数据或卸载会丢失断点；目录版本变化时需要重新核对元数据，进度百分比可能变化。
- 目录扫描仍需遍历本地轻量元数据，缩略图总耗时取决于媒体数量、解码能力、存储提供者与网络。未完成相册断点和下载分片会占用应用存储。
- 仅可信 IPv4 局域网，无账号、鉴权或 TLS；不实时监听目录、不跟踪原文件内容编辑、不自动下载整个相册，也不做跨设备内容去重。
- macOS 完整目录授权 GUI 流程、权限拒绝与恢复、相机、系统分享和导航组合快捷键仍待实机复核；widget 或原生单元测试不能代替系统交互验收。
- 原文件保存到外部目录成功后、数据库登记前若进程被强杀，可能留下未登记副本；重试可能另存同名文件。
- macOS 包未公证。正式公开发布还需 Developer ID 签名与公证、真实双机验收，以及干净环境 / CI 重建。步骤见 [发布与打包](../发布.md)。
