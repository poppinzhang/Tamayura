## 本版变更

完整版本说明见 [CHANGELOG 0.6.1](../../CHANGELOG.md#061)，GitHub Release 正文使用 Tag 内对应版本段落。主要变化包括：

- Android 发布环境为 `setup-android@v3` 显式设置 `packages: platform-tools`，避免请求已移除的 `tools` 包；后续仍安装 API 36 平台及 Build Tools。日常 Android 分支 CI 使用相同步骤，在推送 Tag 前验证 SDK 初始化。
- 新发现设备须确认后同步，支持暂不同步、后续开启和忘记设备；上一次同步失败的设备重新上线时重试一次。
- 相册增加紧凑/详细显示、名称/日期排序和移动端快速滚动；已下载图片优先显示本地原图，同步提示支持关闭和自动收起。
- 支持设备排序和本地媒体删除；删除本地文件保留远端原文件、相册元数据与缩略图。
- macOS 菜单栏与 Windows 托盘保留关闭窗口后的应用进程及下载；后台共享遵循设置，系统睡眠或真正退出仍会中断。
- 统一自动与手动同步规则并显示最后成功同步时间；原文件按 8 MiB 窗口请求、2 MiB 块读取，协议使用 v4。
- 改善异常文件扫描、单张缩略图容错、分页与同步竞争处理，修正真实 gRPC 停滞测试的首块计时假设；生产环境的 30 秒停滞阈值不变。
- 增加三平台 Tag 自动测试、构建和 Pre-release 发布流程，正文取自 CHANGELOG，附带联合 SHA-256 与元数据；Android 本地和 CI 使用新的个人 release 签名。CI 内完成产物和上传核验，取消下载后的重复手工检查；沿用现有 Secrets 与 `GITHUB_TOKEN`，授权后由 Agent 连续执行并等待结果。

## 安装与数据

互联设备须使用同一 **0.6.1** 构建。协议 v4 与 0.5.0 的协议 v3 不互通，不提供旧协议适配。

**Android 首次从 0.5.0 或更早版本切换时，必须先卸载旧版再安装。** 新个人证书与旧签名不同，不能直接覆盖；未设置签名轮换机制。卸载会清除设置、SAF 目录授权、离线缓存、下载记录及未完成分片，需重新选择目录并发现设备；签名变化还可能改变 `ANDROID_ID`，其他设备可能将其视为新设备。后续只有同签名的 release 包才能覆盖安装。

媒体库使用 **schema 7**，按 v1.0.0 前策略清空重建旧库，不迁移历史数据：设置、记住的设备、离线相册、缩略图与下载历史索引清空；重新发现的设备需要再次确认同步。独立下载任务库保持 schema 3，媒体库重建不清空该任务库，但卸载或清空应用数据会清除任务与分片。**外部共享目录中的原始媒体及已保存的接收文件保留。**

macOS 完整解压 ZIP，将 `Tamayura.app` 放入“应用程序”；未公证包被系统拦截时，确认来源与校验结果后通过系统“隐私与安全性”确认，不关闭全局 Gatekeeper。Windows 完整解压 ZIP 后运行 EXE，保留 SQLite、插件 DLL、Flutter 引擎和 `data`，并安装相应 Visual C++ x64 运行库；只在可信专用网络中允许防火墙访问。

## 已知限制与验收边界

- 当前分发策略为试用性质的 Pre-release，macOS 未公证、Windows 未签名，不是稳定公开发行或应用商店版本。
- 本版真实设备的发现上下线、目录授权、跨平台传输、断网/睡眠恢复、系统菜单、扫码和系统分享尚未验收。macOS Sequoia / Intel、Windows 10 1809、无开发工具的用户机及 Android 厂商电源策略仍需真实环境验证。
- Android 后台共享受系统电源策略约束；桌面共享与下载要求应用运行且系统清醒，不提供后台系统服务、开机自启或远程唤醒。
- 2 MiB 读取块仍需真机测量吞吐与内存表现；单路约低于 70 KiB/s 时可能触发 30 秒停滞重连。连续 30 分钟无数据后下载失败，需手动重试。
- 分片和接收文件仍可能同时占用约两倍空间，容量预检不预留空间，部分 Android 文档提供者无法查询容量；保存与数据库登记不是跨系统事务。
- Android 文档提供者对缺失文件返回原因不明的异常时保留保存记录供重试；macOS / Windows 单个文件权限或独占错误仍使同步稍后重试。
- Windows 仅支持 x64，不提供相机扫码、系统分享面板或安装器。仅可信 IPv4 局域网，无账号、鉴权或 TLS。
