# 多语言

## 范围

界面支持简体中文、日本語和 English。默认「跟随系统」，可在**设置 → 外观 → 语言**中选择固定语言；切换立即生效，已打开的页面同步更新，选择保存在本机并在重启后保留。

跟随所选语言的内容：

- Flutter 界面文案、无障碍标签和提示，以及 Material 组件自带文案（返回按钮提示、文本选择菜单、开源许可页等）。
- 日期与数量格式：相册快速滚动的月份与日期、详细模式卡片日期使用对应语言的 CLDR 格式，例如 zh「2026年10月17日周六」、ja「2026年10月17日(土)」、en「Sat, Oct 17, 2026」；最后同步时间和详细信息中的修改时间保持数字格式。英文数量使用单复数形式。
- 控制器、服务层和传输记录生成的错误与状态提示，包括 Android 后台下载引擎写入的任务错误。
- 原生文案：Android 通知、通知渠道名称、分享面板标题、更新安装状态及存储错误；macOS 菜单栏图标与菜单、目录选择面板和错误；Windows 托盘提示与菜单、目录选择对话框标题和错误。

应用名在中文界面称「玉响」；日文和英文界面句子中称 Tamayura，顶栏副标题日文为「たまゆら」，英文不显示副标题。设备名、共享文件夹名和文件名来自用户或系统，不做翻译。

## 语言解析

偏好取值为 `system`、`zh`、`ja` 或 `en`，各端使用同一规则：

1. 选定语言时直接使用。
2. 跟随系统时，按系统首选语言列表顺序取第一个语言代码为 `zh`、`ja` 或 `en` 的语言；任何中文变体（包括繁体）使用简体中文。
3. 列表中没有受支持语言时使用英文。

| 位置 | 实现 | 系统语言来源 |
| --- | --- | --- |
| Flutter | `lib/l10n/app_locale.dart` 中的 `resolveAppLocale` | `PlatformDispatcher.locales` |
| Android | `AppText.resolve` | `LocaleList.getDefault()` |
| macOS | `AppText.resolve` | `Locale.preferredLanguages` |
| Windows | `app_text::Resolve` | `GetUserPreferredUILanguages` |

## Flutter 实现

- 使用 Flutter gen-l10n。`l10n.yaml` 指定模板 `lib/l10n/app_zh.arb`（包含占位符元数据），翻译为 `app_ja.arb` 与 `app_en.arb`，生成代码位于 `lib/l10n/generated/` 并随源码提交。`pubspec.yaml` 启用 `generate: true`，`flutter pub get` 会重新生成；也可单独运行 `flutter gen-l10n`。不要手工修改生成文件。
- `lib/l10n/app_locale.dart` 定义 `AppLanguage`、解析函数、`AppLocale` 和 `context.l10n`。界面通过 `context.l10n` 读取文案，语言变化时依赖它的组件自动重建；服务层在生成提示时读取 `AppLocale.strings`，由控制器同步当前偏好。
- 偏好保存在设置表的 `language` 键。控制器初始化读取后立即生效，读到无效值时按跟随系统处理；`setLanguage` 保存失败时保留原语言并显示可重试的提示。根组件转发 `didChangeLocales`，跟随系统时刷新界面。
- `MaterialApp` 始终使用模型给出的明确 locale，并加载应用、Material、Cupertino 与 Widgets 本地化代理。
- 更新页和原图预览只保存状态种类，构建时按当前语言显示。
- 媒体详情弹层在自己的构建上下文中读取翻译，打开后也随语言变化更新；下载空页面可滚动，在窄屏、大字号下仍能查看完整说明并返回相册。
- `DIR_OVERLAP`、`FILE_CHANGED`、`SCAN_CANCELLED` 三类跨平台错误码在 `describeError` 中统一按当前语言描述；其它平台错误使用原生层已本地化的消息。

## 原生实现

Dart 在启动、切换语言以及跟随系统时系统语言变化后，通过 `tamayura/platform` 的 `setLanguage` 发送偏好。调用失败时原生文案保持之前的语言，不影响启动和语言切换，下次启动或切换时再次发送。

### Android

- 字符串资源位于 `res/values`（英文，兼作回退）、`res/values-zh` 与 `res/values-ja`，三份键保持一致。
- `AppText` 将偏好保存到 SharedPreferences `tamayura-language`，按解析结果创建本地化 Context。后台共享服务和后台下载 JobService 在界面未启动时也使用上次保存的选择；后台下载的 Dart 引擎在 `ready` 返回值中取得语言。
- 切换语言时重命名已存在的通知渠道，并刷新后台共享通知；尚未创建的渠道不会因此创建。下载通知在下一次进度更新时使用新语言。
- `StoragePaths`、`SharedCatalog`、`TransferPolicy`、`DeviceIdentity` 保持不依赖 Android 运行时，异常实现 `LocalizedText` 携带字符串资源，在上报给 Dart 时转换为当前语言；更新安装异常同样只携带资源与错误码。

### macOS

- `Runner/AppText.swift` 保存三种语言的文案表，偏好保存在 UserDefaults `tamayura.language`，原生测试可替换存储位置。
- 菜单栏图标及菜单在启动时使用上次的选择，收到语言变化通知后更新；目录选择面板、错误提示在生成时读取当前语言。
- `PlatformFailure.io` 先读取 `errno` 再查找文案，避免查找过程影响文件、权限与空间错误的分类。
- 相机与本地网络权限说明使用 `en.lproj`、`zh-Hans.lproj`、`ja.lproj` 中的 `InfoPlist.strings`，由 macOS 按系统语言选择。

### Windows

- `runner/app_text.*` 保存三种语言的文案表，偏好仅保存在进程内；启动后到 Dart 发送偏好前按系统语言显示。
- 托盘菜单在每次打开时生成；托盘提示文字在收到 `kLanguageChangedMessage` 后通过 `NIM_MODIFY` 更新；目录选择对话框标题在打开时读取当前语言。

## 新增或修改文案

1. 在 `lib/l10n/app_zh.arb` 添加键和中文；带占位符的文案同时添加 `@键` 元数据。在 `app_ja.arb`、`app_en.arb` 添加对应翻译，英文数量使用 ICU plural。
2. 运行 `flutter gen-l10n` 或 `flutter pub get`，将 ARB 与生成代码一起提交。
3. 界面使用 `context.l10n`，服务层使用 `AppLocale.strings`，不要在代码中写死面向用户的文案。
4. 原生文案同时更新 Android 三份 `strings.xml`、macOS `AppText.swift` 与 Windows `app_text.cpp`。

## 测试

- `test/flutter_test_config.dart` 将测试中的系统语言固定为简体中文，原有中文断言同时检查中文文案未被改动。
- `test/language_test.dart`：解析规则、三份 ARB 的键与占位符一致、英文不含中文、日文不含简体专用字；控制器的读取、保存、失败重试、重复选择、原生下发、系统语言变化；服务层错误、地址校验、更新取消和持久化任务错误随语言变化。
- `test/language_ui_test.dart`：语言菜单显示各语言自称并即时切换、跟随系统的首选语言、已打开页面、媒体详情弹层与 Material 文案同步、日期和数量格式，以及三种语言在 320×640、640×320 和 1.6 倍字号下无溢出；下载空页面还验证滚动后能点击返回相册。
- `test/transfer_resilience_test.dart`：Android 后台下载引擎按原生返回的语言写入任务错误；`test/platform/windows_bridge_test.dart` 检查三端桥接发送 `setLanguage`。
- 原生测试：Android `AppTextTest` 覆盖解析、资源选择、系统语言、无效偏好、纯 JVM 异常文案和通知渠道重命名；macOS `Tests/AppTextTests.swift` 覆盖文案完整性、解析、保存和 `errno` 分类；Windows `tests/app_text_test.cpp` 与托盘测试覆盖解析、文案完整性和提示文字更新。macOS 原生检查还核对三种 `InfoPlist.strings` 已打包。

自动化测试不能替代真机上的字体显示、系统通知、菜单栏、托盘和权限弹窗验收。

## 已知限制

- 已保存的下载任务错误、后台共享失败原因和 Android 更新安装状态等持久化消息保留写入时的语言。
- Android 后台下载引擎仅在 `ready` 时读取语言偏好，不接收后续应用内语言切换。已运行引擎新生成的任务错误可能沿用启动时语言；后续新建引擎读取最新偏好，文件传输不受影响。
- 系统组件按操作系统语言显示：macOS 权限弹窗、macOS 应用主菜单（沿用 Flutter 模板的英文菜单）、系统文件选择器按钮和系统分享面板不跟随应用内选择。
- Windows 存储层的部分内部诊断仍为英文；常见的目录重叠、文件变化和扫描取消已在 Dart 统一描述。
- 繁体中文系统显示简体中文，其它未支持的系统语言显示英文。日文和英文翻译尚未经过专业校对。
