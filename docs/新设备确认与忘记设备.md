# 新设备确认、上线重试与忘记设备

## 新设备确认

通过 mDNS / DNS-SD 自动发现的新设备不会立即同步相册：

1. 收到未记住设备的 `found` 广播后，控制器先用 `GetIdentity` 核验它确实是该 ID 且协议兼容；核验失败（离线、协议不兼容、地址属于另一台设备）不写入数据库，也不出现在设备列表。
2. 核验通过后以「待确认」（`pending`）保存，出现在「设备」页面，并弹出一次「发现新设备」提示。
3. 选择「开始同步」写入 `approved` 并立即发起一次同步，之后按自动同步间隔计时；选择「暂不同步」写入 `declined`，设备保留在列表中，不再提示、不自动同步。
4. 点击对话框外部关闭提示不作决定，设备保持「待确认」；同一次运行中不会再次弹出，下次启动后再次发现时重新提示。
5. 待确认或已拒绝的设备在设备卡片上显示「开启同步」按钮，菜单中也有「开启相册同步」，随时可以开启。

用户主动输入 IP 地址或扫描二维码属于明确的连接请求，身份核验后直接视为已确认并同步；重试一次失败的手动地址同样如此。已确认的设备才会参与启动、返回前台、定时器、手动刷新和自动发现触发的同步。

确认状态保存在 `peers.sync_approval`（`pending` / `approved` / `declined`）。只有 `rememberDiscoveredPeer` 会插入 `pending` 行，已有行只更新名称和地址，保留原决定；其余写入（同步开始、目录提交）插入的行默认 `approved`。普通的地址、名称和尝试时间写入都不会改变用户的决定。

## 上线时重试失败的同步

自动同步仍按设备计时（见 [自动与手动同步](自动与手动同步.md)），失败也计入间隔。例外是上线的「边沿」：

- 控制器记录当前发现会话中正在广播的设备 ID。某设备的 `found` 事件不在该集合中时视为一次上升沿；收到 `lost` 或停止发现（关闭共享网络、移动端进入后台且未开启后台共享）时清除。
- 上升沿到来时，如果该设备已确认且上一次同步尝试失败，即使未到间隔也立即重试一次。重复的广播、地址或名称更新不是边沿，只做身份与在线核验，不会轮询一台持续失败的设备。
- 边沿到来时该设备正在同步，则记下该边沿；这次尝试失败后补做一次重试，成功则不再处理。
- 「上一次尝试失败」保存在 `peers.last_sync_failed`：记录尝试时间时置 1，完整目录提交或对端确认目录未变化时清零。崩溃或中断的尝试同样视为失败，重启后第一次发现该设备即可重试。

因此一台休眠的手机在应用启动时连接失败，醒来重新广播时会立即同步，不必等待默认的 10 分钟间隔；在线但持续失败（例如对端某个文件暂时无法读取）的设备只在下一次下线再上线时重试。重新启动发现会话也会产生新的边沿：移动端未开启后台共享时，每次回到前台都会对上次失败的设备重试一次。

## 忘记设备

设备卡片菜单提供「忘记设备」，确认后：

- 先停止该设备的在线探测，关闭并等待它正在进行的同步结束，避免迟到的目录写入或在线结果重新创建设备。
- 在一个 SQLite 事务中删除该设备的 `sync_sessions`（级联删除 `sync_media`）、`media` 和 `peers` 行，并清理不再被引用的缩略图；从设备排序中移除；若当前正在查看该设备或其合集则回到全部设备。
- 保留下载历史（`downloads`）、下载任务及已保存到本机的文件；不会通知或修改对端。
- 删除失败时设备保持原状并显示错误，可以重试；进行中时卡片菜单不可重复操作。

被忘记的设备再次出现在局域网中（重新上线或下次启动后的发现）时作为新设备处理：重新核验身份、以「待确认」保存并再次提示。

## 数据库

媒体库 schema 升至 7，`peers` 新增 `sync_approval`（默认 `approved`，带取值检查）与 `last_sync_failed`（默认 0）。按 v1.0.0 前策略直接重建旧媒体库，不提供迁移。
