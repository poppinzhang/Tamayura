# 桌面托盘与窗口生命周期

macOS 和 Windows 在关闭主窗口后保留应用进程、Flutter 引擎、页面状态和进行中的下载，该功能自 0.6.1 起随安装包发布。Linux 在 1.0.0 源码中加入：桌面提供状态托盘时行为相同，没有托盘时关闭窗口即退出；0.9.6 及更早安装包不含 Linux 程序，本次实际发布状态见 [1.0.0 发布记录](releases/1.0.0.md)。

Windows 单实例启动为 `CHANGELOG.md` 的 `unstaged` 改动，尚未随安装包发布：同一用户、同一登录会话中再次运行玉响，会恢复并激活已有窗口，后启动的进程随即退出。已有窗口在托盘隐藏或最小化时同样可恢复，最大化状态保留。旧版进程不参与新的互斥机制，首次使用更新后的程序前须先退出旧版。

## 使用方式

| 操作 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 关闭窗口 | 点击红色关闭按钮或按 ⌘W，隐藏主窗口 | 点击关闭按钮或按 Alt+F4，隐藏主窗口 | 有状态托盘时隐藏主窗口；没有托盘时退出应用 |
| 重新打开 | 右上角玉响菜单栏图标 →「打开玉响」，点击 Dock 图标或通过 ⌘Tab 激活 | 点击通知区域的玉响图标，或右键 →「打开玉响」；图标可能在系统折叠菜单中 | 点击托盘图标或菜单 →「打开玉响」，或再次从应用菜单启动玉响 |
| 真正退出 | 菜单 →「退出玉响」，或 ⌘Q | 托盘右键菜单 →「退出玉响」 | 托盘菜单 →「退出玉响」，或 Ctrl+Q |

后台共享仍由「设置 → 后台共享」控制，默认关闭，保留用户当前选择。开启后，关闭、隐藏或最小化窗口仍提供局域网文件；关闭此项后，隐藏窗口会停止 gRPC 监听、设备发现和相册同步。已开始的接收下载独立运行，两种设置下都能继续，恢复窗口后可查看进度。共享开启时既有自动同步间隔规则继续生效。

真正退出会结束进程和网络服务；系统睡眠期间也无法保证传输。此功能不添加开机自启、后台系统服务或阻止系统睡眠的行为。macOS 沿用现有共享与下载的 App Nap 活动保护。

## macOS 实现

`AppDelegate` 在应用启动完成后创建并持有 `DesktopStatusItem`。菜单栏使用 `NSStatusBar` / `NSStatusItem`，1.0.0 源码使用 18pt 的「響」透明镂空 SVG 模板图像，保留素材原有圆角；AppKit 按菜单栏外观自动着色，字形镂空处透出菜单栏背景，独立于 Flutter 手动主题。资源规则见 [应用图标](应用图标.md)。`DesktopWindowResidence` 强引用原有主窗口，关闭时通过 `NSWindowDelegate.windowShouldClose` 调用 `orderOut` 并返回 `false`，避免销毁窗口、Flutter view controller 和引擎。最后一个窗口关闭不再自动结束应用。

恢复入口共用同一窗口：激活应用、恢复最小化状态并前置窗口。Dock/Finder 重新打开由 `applicationShouldHandleReopen` 处理，应用激活时也恢复隐藏主窗口，支持 ⌘Tab。全屏关闭先退出全屏，收到退出完成事件后再隐藏，避免留下空白 Space；退出过程中重新打开会撤销待隐藏动作，退出全屏失败则保留可用窗口并允许重试。

AppKit 会将菜单栏弹出菜单计入应用可见性。Dart `AppLifecycleCoordinator` 在 macOS 的前台事件中通过 `isMainWindowVisible` 查询真正的主窗口，菜单弹窗不会让隐藏窗口恢复共享或刷新相册。查询失败按非前台处理，下一次激活重试；生命周期代次检查丢弃关闭窗口之后才返回的旧可见性结果，避免快速开关窗口时重新启动共享。

退出菜单调用系统标准 `NSApplication.terminate`，继续经过 Flutter 的应用退出流程；窗口关闭拦截不阻止 ⌘Q、应用菜单或系统正常结束应用。应用结束时移除状态图标。

## Windows 实现

`DesktopTray` 由 `FlutterWindow` 持有，复用原有橙色程序图标，通过 `Shell_NotifyIconW` 注册通知区域图标和 version 4 回调。托盘消息先于 Flutter 插件窗口处理器处理：`WM_CLOSE` 在托盘可用时仅执行 `ShowWindow(SW_HIDE)`，原窗口和引擎继续存在；鼠标点击及键盘激活恢复窗口，最小化时使用 `SW_RESTORE`，其他情况保留最大化状态。

Flutter 同时跟踪宿主和子窗口的可见性，子窗口不会自动处理父窗口的 `WM_SHOWWINDOW`。Runner 将同一可见性消息通过引擎的 `ProcessExternalWindowMessage` 同步给子窗口，再保留父窗口的标准处理，确保隐藏时 Dart 收到 `hidden`，后台共享开关不会因残留的子窗口状态而失效。

右键菜单使用原生弹出菜单。「退出玉响」设置退出状态后投递 `WM_CLOSE`，由普通窗口销毁路径结束应用，避免在菜单回调执行期间销毁自身。正常销毁删除托盘图标并释放平台资源、Flutter 引擎。系统注销/关机经过正常窗口处理路径，取消注销后恢复关闭到托盘行为。

资源管理器重启后响应 `TaskbarCreated` 重新注册图标。初始注册或版本协商失败时，关闭窗口沿用正常退出行为，避免隐藏后无法找回；资源管理器重启后恢复图标失败则主动显示隐藏窗口。菜单创建失败也恢复窗口。图标不可用时，不承诺关闭后继续运行。

### 单实例与重复启动（未发布源码）

`windows/runner/single_instance.cpp` 的 `SingleInstance` 在 Runner 入口、COM 和 Flutter 初始化之前取得命名互斥锁。锁名使用 `Local` 会话命名空间与当前用户 SID，不包含程序路径或版本号；采用该机制的不同路径、不同版本共用一个实例。同一登录会话中的并发启动只有一个进程取得锁；正常退出释放锁，进程崩溃后由 Windows 标记为已放弃，后续启动可重新取得。不同用户或不同登录会话不属于该保证范围。

首个进程在 Flutter 初始化前创建专用 message-only 窗口，后续进程通过它发送激活消息，不按可变的窗口标题或托盘可见性查找主窗口。首帧之前收到的请求暂存，在主窗口就绪后处理。后续进程先调用 `AllowSetForegroundWindow` 将可用的前台权限交给首个进程，再请求显示窗口；重复启动和托盘打开共用 `ShowAndActivateWindow`，最小化时还原，其他情况保留最大化状态。Windows 仍可能按前台焦点策略拒绝抢占，此时显示窗口并闪烁任务栏提示，不承诺所有系统状态下都能强制取得焦点。

后续进程收到激活确认后退出，不再初始化 Flutter、数据库或网络服务。首次进程尚未响应时最多等待 10 秒；期间若其退出或崩溃，等待进程重新竞争锁。获取用户身份、创建互斥锁或激活端点失败，以及无权限或超时无法唤醒时，显示中文、日文或英文的原生错误并退出，不绕过互斥继续启动。该改动不涉及数据库 schema、配置格式、gRPC 协议或已有用户文件。

## Linux 实现

`DesktopTray` 由 `MyApplication` 持有，在 GtkApplication 的会话总线连接上导出 StatusNotifierItem（`/StatusNotifierItem`）和 `com.canonical.dbusmenu` 菜单（`/MenuBar`），图标以 ARGB32 像素随属性提供，不依赖 libappindicator 或图标主题安装。它监视 `org.kde.StatusNotifierWatcher`，注册成功且 `IsStatusNotifierHostRegistered` 为真时才报告托盘可用；KDE Plasma、Ubuntu 默认桌面的 AppIndicator 扩展、Xfce、Cinnamon、MATE、Budgie 及多数 Wayland 状态栏提供该宿主，原版 GNOME 需另装扩展。

托盘使用新版「響」SVG 直接导出的黑、白两套 PNG，保留素材原始圆角及 alpha。浅色 GTK 外观使用黑底白字，深色外观使用白底黑字；主题改变后更新图像并发出 `NewIcon`，不受 Flutter 手动主题影响。尺寸与资源布局见 [应用图标](应用图标.md)。

窗口的 `delete-event` 处理器先于 Flutter 自身的处理器连接：托盘可用且不是主动退出时只 `gtk_widget_hide` 并拦截事件，引擎、页面和下载继续；否则交给 Flutter，按常规请求 Dart 退出。单击图标（`Activate`）、`SecondaryActivate` 或菜单「打开玉响」显示并前置同一窗口；宿主通过 `ProvideXdgActivationToken` 提供令牌时用于 Wayland 聚焦，X11 使用服务器时间避免焦点抢占拦截。「退出玉响」和 Ctrl+Q 设置退出状态后发出窗口关闭请求，仍经过 Flutter 的退出流程；窗口尚未实现时直接结束 GtkApplication。

监视器消失、宿主注销或注册失败时托盘变为不可用；此时若窗口处于隐藏状态会主动重新显示，之后关闭窗口按常规退出。切换语言后发出 `NewTitle`、`NewToolTip` 与菜单 `LayoutUpdated`。Release 构建为单实例 GtkApplication，从应用菜单再次启动会激活并显示已有窗口。GTK 窗口隐藏、最小化与恢复由 Flutter 引擎转换为 `hidden` / `inactive` / `resumed`，Dart `AppLifecycleCoordinator` 按与 Windows 相同的桌面规则启停共享。
