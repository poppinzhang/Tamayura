# Android 后台共享

macOS 的窗口后台行为、App Nap 保护与系统睡眠边界见 [macOS 实现与验收](macOS原型.md#后台运行app-nap-与睡眠)。

## 使用方式

「设置 → 文件与存储 → 后台共享」默认关闭。

- 开启：使用 `connectedDevice` 前台服务维持本机已选共享目录的 gRPC 与设备广播，锁屏或切换应用后继续提供元数据、缩略图及原文件。
- 关闭：立即停止前台共享服务、释放 CPU 唤醒锁并移除运行通知；界面可见时仍正常共享，进入后台后停止监听、设备发现及在途目录同步/探测，恢复通常的后台省电行为。独立的、用户已发起的接收下载任务仍按原有 UIDT 规则运行。
- 通知内可停止后台共享，开关与运行状态会随之更新。首次开启可以允许通知；拒绝通知不会阻止前台服务运行，通知栏是否显示由系统控制，仍可在应用设置里关闭。
- 开关保存在 Android 本机偏好中。再次主动打开应用时恢复之前的开启选择；没有加入开机广播或纯局域网远程唤醒。
- 若系统仍限制电池优化，界面显示说明和「电池设置」入口。用户在系统中设置后，返回应用会重新读取豁免状态。关闭共享不会擅自修改用户的系统电池设置。

只共享已授权的目录，仍仅面向局域网。元数据保持按既有启动/刷新机制更新，不增加周期扫描。

## 原生服务与引擎生命周期

`AndroidRuntime` 在应用进程内持有唯一主 FlutterEngine，以及 SAF 媒体读取、NSD 与平台通道。`MainActivity` 通过 `provideFlutterEngine` 使用这个引擎，`shouldDestroyEngineWithHost` 返回 false；目录选择器、系统分享、通知权限及系统设置仍由 Activity 处理。Activity 销毁不会清理服务仍需使用的媒体快照或设备发现。

`BackgroundSharingService` 声明 `connectedDevice` 类型，Manifest 包含 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_CONNECTED_DEVICE`、`CHANGE_NETWORK_STATE` 与 `WAKE_LOCK`。开启时先调用 `startForeground`、持有不点亮屏幕的 `PARTIAL_WAKE_LOCK`，再确保运行引擎。平台调用只有在服务实际启动后才确认运行；启动被拒绝、超时或异常时回滚开关，并清理通知和锁。

前台服务使用 `START_STICKY`；系统普通回收后可重建进程与引擎。这个机制不等同于无限存活，也不用于绕过用户强行停止。服务被用户关闭后使用 `START_NOT_STICKY`，不再维持运行。

没有使用新版 Android 在息屏场景下无可靠作用的 Wi-Fi 性能锁，也没有为了保活增加轮询定时器、假音频或定时闹钟。设备发现使用系统 NSD；不指定单个 Network，服务查询由系统在支持的网络上维护。

## Flutter 状态与启停

`tamayura/platform` 增加：

| 方法 | 结果 |
| --- | --- |
| `sharingStatus` | `enabled`、`running`、`batteryExempt`，以及可选 `error` |
| `setBackgroundSharing` | 输入 `enabled`，返回原生确认后的状态 |
| `openBatteryOptimizationSettings` | 打开系统电池优化设置 |

`tamayura/sharing` 事件通道在订阅时发送当前快照，并上报通知停止、服务启停等状态。偏好只有一个原生来源，不再在 SQLite 中保存副本。

控制器以「界面在前台或共享服务实际运行」决定是否提供网络服务。冷启动的无界面引擎不会仅因为偏好为开启就提供服务；需原生确认 `running`。前台状态从 Flutter 生命周期读取，`inactive` 暂时失去焦点不触发停机，`hidden` / `paused` / `detached` 则按共享开关处理。

启停、刷新与目录变更的网络操作串行执行。异步扫描/启动结束时再次检查当前条件，防止关闭后晚到的启动重新开放监听。系统状态读取带版本校验，旧查询不能覆盖更新的通知停止事件。网络停机也会终止在途客户端和服务端请求，避免等待大文件传输结束才能进入省电状态。

## mDNS 丢失与在线判断

mDNS `lost` 仅表示发现信息丢失，不立即认定设备离线。控制器对已记住的 IP 与实际端口发起轻量 gRPC 身份核验，最长等待 8 秒；确认失败、超时或设备 ID 不符才标记离线。重复丢失事件合并，不下载整个目录来探测状态。

重新发现、成功连接、网络停机与控制器销毁会使旧探测失效。目录同步的权限/扫描错误不会直接等同断线，而会复核可达性；原有离线相册缓存不受影响。关闭网络会主动关闭探测和同步客户端，旧操作也不能清理重启后的新连接或覆盖新状态。

## Android 边界

前台服务不自动解除全部 Doze 或厂商电源限制。长时间息屏需结合系统电池豁免，并以具体手机验证。正常锁屏后已授权文件通常仍可读取；设备重启后首次解锁前，常规加密存储尚不可用。应用被系统设置中的「强行停止」后需用户再次主动启动，不承诺 B 的请求能唤起已停止的 A。

## 验证

自动化覆盖开关读写、启动确认、失败回滚、启动超时、通知停止、锁与通知释放、Sticky 恢复；Flutter 覆盖前台/后台启停、无界面恢复、慢启动与停止竞态、旧状态读取、保存失败、电池状态返回更新、小屏大字，以及 mDNS 探测与同步竞争。真实本地 gRPC 测试核验后台目录/原文件读取和停止时中断慢请求。

2026-10-10 本机验证记录：

- `flutter analyze` 无问题；全部 Flutter 测试 210 项通过；应用 Android 原生测试 58 项通过；调试 APK 构建成功。
- Android 16 AOSP ATD 只读模拟器中，通过界面开启共享并拒绝通知权限后，锁屏仍能从宿主发起 gRPC 身份与目录请求。
- 为测试镜像启用 Doze，加入应用电池豁免后强制进入 `IDLE`，同样可响应 gRPC。此结果不代表没有电池豁免或厂商真机也能全天可达。
- 结束测试应用进程后，系统以新进程恢复共享前台服务；Activity 为 `DESTROYED`、未附着新进程时，gRPC 仍可响应。
- 在界面关闭共享后锁屏，gRPC 不再可达，系统中没有共享 ServiceRecord，也没有 `Tamayura:BackgroundSharing` 唤醒锁。
- ATD 不含完整通知栏与文件夹选择器；通知停止由原生和控制器测试覆盖，真实授权媒体的锁屏读取需下述双机验收。模拟器请求的是空目录；媒体字节、慢读取及暂停下载的取消由真实本地 gRPC 自动化验证。

Android 16+ 真机仍需完成以下验收，模拟器不能代替厂商系统和真实 Wi-Fi：

1. A 开启后台共享，B 获取目录、缩略图、小照片和超过 50 MiB 的视频；A 锁屏至少 30 分钟后重复。
2. 在电池优化开启/豁免、通知允许/拒绝下分别验证，并检查提示符合实际状态。
3. 划走 A 的任务卡片、旋转/重建页面，再从 B 下载；验证系统普通回收后恢复与强行停止后的明确离线。
4. 在 A 界面、通知栏分别关闭共享，核验后台端口停止、唤醒锁释放，大文件请求中断后 B 可重试；再次打开正常工作。
5. Wi-Fi 断开/重连、IP 改变、mDNS 暂时消失时，对端可达性判断与重连正确。
6. 撤销目录授权时保留 B 的缓存并报告错误，不把相册权限失败直接误判成设备离线。
