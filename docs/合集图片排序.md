# 合集图片排序

进入相册中的任一合集后，使用「排序」菜单切换名称升序、名称降序、日期升序或日期降序。移动端与桌面端使用相同入口，当前选项显示在按钮和菜单勾选状态中。默认采用日期降序，最新文件在前；同一运行期间切换合集、设备或刷新仍沿用选择，重新启动恢复默认值。

## 排序规则

- 名称依据完整文件名（包含扩展名），采用 SQLite `BINARY` 字典序，区分大小写，不按所在子目录排序。数字也作为文字比较，例如升序时 `photo10.jpg` 在 `photo2.jpg` 前；中文不按拼音排序。
- 日期依据来源文件的修改时间 `modifiedMs`；升序由旧到新，降序由新到旧。当前元数据没有独立的 EXIF 拍摄日期，因此不使用拍摄日期、下载时间或同步时间。
- 名称或日期相同的项目，继续按设备 ID、媒体 ID 升序排列，确保分页顺序稳定。合集中已有的视频沿用同一规则。

## 实现

`MediaSortOrder` 定义四种排序方式，`TamayuraModel` 暴露当前排序及切换中的状态。`AppController` 把排序传给 `TamayuraRepository.listMediaPage`，数据库在设备与共享目录筛选后的整个媒体集合上排序，再读取每页 60 项。正式缓存和已就绪的同步暂存数据共用排序查询，离线也可切换。

`MediaCursor` 保存排序方式、名称、修改时间和设备/媒体标识。游标条件与 `ORDER BY` 使用相同字段、方向及比较规则；拒绝将一种排序的游标用于另一种排序，避免跨页遗漏或重复。无需更改数据库结构、通信协议或保存额外设置。

切换排序时使旧分页请求失效，暂停新的加载更多操作，从第一页重新加载并回到顶部，同时退出本地删除多选状态。读取成功后才更新排序选择和列表；失败时保留原来的列表、选择及分页位置，显示错误，并允许再次选择重试。旧请求迟到的结果或错误不会覆盖新列表。排序不会下载媒体或改变已保存文件。

## 验证

仓储测试覆盖四种排序、同值稳定顺序、跨页游标、大小写/数字/非 ASCII 名称、设备与合集筛选、空集合以及正式/暂存数据混合。控制器与界面测试覆盖超过两页的合集、切换后的分页重置、旧分页竞争、读取失败重试、四项菜单操作和移动/桌面布局。
