# 应用更新

本功能已随 0.8.0 Pre-release 发布，未包含在 0.7.0 安装包中；实际发布结果与验收范围见 [0.8.0 发布记录](releases/0.8.0.md)。首次需手动安装包含本功能的完整发行包，之后可从「设置 → 检查更新」更新。本次不修改数据库或局域网协议。

## 用户流程

1. 用户点击「检查更新」，应用读取实际安装版本并查询公开仓库的 GitHub Releases API，从 1.0.0 起只选择正式 Release，排除 Pre-release 和草稿。没有新版本才显示「已是最新版本」；网络、限流、元数据或附件错误均明确提示并可重新检查。
2. 发现新版本后显示确认对话框，更新页面保留 Release 更新说明。用户选择「暂不更新」不会下载、安装或打开浏览器。
3. Android、Windows 确认后从该版本附件下载完整安装包，显示进度，允许取消。校验完成后自动交给对应原生安装机制。权限或准备失败保留已下载文件，允许重试安装；「重新检查」可重新获取和下载此版本。
4. macOS 与 Linux（1.0.0 源码）确认后只通过默认浏览器打开该版本的 GitHub Release 页面，不在应用内下载或安装。浏览器无法打开时可重试。

更新查询和下载安装包需要互联网，使用 HTTPS；局域网媒体发现与 gRPC 传输规则不变。只在用户主动操作时检查，不在启动时后台轮询、强制升级或使用差分包。

## 版本和附件

`lib/update/update_service.dart` 负责查询、解析、选择、下载及校验。版本限定为当前发布规范的 `v主版本.次版本.修订号`，按整数分段比较，不能以发布时间或字符串顺序判断。当前发布规范禁止同版本重发不同构建号，因此只有版本号严格升高才提示更新；Android 另要求构建号升高。

继续读取 Releases 列表并按严格版本号选择最高的正式版本，不依赖 `/releases/latest` 的单条结果或发布时间排序。每页最多 100 项、最多读取 5 页，达到上限且未确认列表结束时显示错误，不声称当前已经最新。即使 Pre-release 版本号更高也忽略它；最高正式版本的附件不完整时明确失败，不静默退到旧版本。

Android 和 Windows 读取同一 Release 的 `release.json`，核对 tag、版本、构建号、平台、架构、安装包名称、大小和 SHA-256，并与 GitHub 附件元信息对应。只下载实际程序附件，忽略 GitHub 自动提供的源码归档。macOS 与 Linux 根据 Release 的严格版本标记和仓库页面地址直接打开页面，不读取 `release.json`。Release 新增 Linux 包后，`release.json` 的 `platforms` 多出 `linux-x64`、`linux-arm64` 两项；Android 和 Windows 只按自身平台键与精确文件名查找，已安装版本不受额外平台与附件影响。

连接只允许 HTTPS、官方 GitHub API/仓库地址及允许的 GitHub 附件 CDN 重定向；拒绝凭据、其他仓库路径和非预期地址。无个人 Token、账号登录或独立更新服务器。JSON 有大小和读取时限，安装包限制 2 GiB；下载连接或连续无数据 30 秒超时报错，有持续数据时无固定总时限。

安装包流式写入原生私有更新目录下本次独立的 `update-*` 子目录。下载期间使用 `.part`，只有大小和 SHA-256 同时通过后才改成正式文件名。取消和下载失败清理本次临时目录，不影响媒体下载暂存、用户目录或已保存媒体。

SHA-256 用于验证下载完整性，信任来源仍是 GitHub 仓库和 HTTPS；本次不引入额外更新签名密钥。Android 进一步校验已安装应用签名；Windows 当前发行包未签名，不能将校验和描述成独立发布者签名。

## 平台安装

### Android

`tamayura/updates` 通道由 `AppUpdateInstaller` 处理。安装前核对私有路径及非链接文件、SHA-256、APK 包名、版本、构建号和当前签名；拷入系统 PackageInstaller 会话时再次校验 SHA-256。

需要 `REQUEST_INSTALL_PACKAGES`。首次未授权时打开系统的安装来源设置，返回后用户可点「重试安装」，不重复下载。使用系统安装确认页面，不能承诺静默安装；系统拒绝、用户取消、存储不足、签名冲突、会话中断均转换为持久安装状态。页面在安装期间及恢复前台时读取状态，不将“已提交系统”显示为“已经安装成功”。

安装前不主动销毁当前控制器，用户拒绝系统确认后仍可继续使用原应用。系统真正覆盖安装会终止应用进程，共享和传输受到影响。release 包只能覆盖同签名应用，debug 包或旧签名包不得自动卸载重装；卸载的影响仍遵循发布文档。

### Windows

`WindowsUpdate` 与随包的 `tamayura-update.ps1` 使用系统 Windows PowerShell 5.1。新 ZIP 内增加 `tamayura-bundle.json`，由打包脚本在构建后生成，包含版本及全量发行文件大小和哈希；清单位于 ZIP 内部，不增加外层 Release 附件。

应用需放在可写的独立本地目录，目录及父目录均需允许更新操作。当前目录必须有完整清单且文件未被修改，不能混入用户文件、符号链接或 junction。用户可将完整应用移到可写目录后重试；不自动请求管理员权限。仅运行 `flutter run` 或自行拷贝缺少清单的调试目录不具备自动覆盖更新条件。

准备阶段重新核对 ZIP SHA-256、安全展开、x64 EXE 版本、必需 DLL/资源及全量文件清单，拒绝路径穿越、重复路径、链接、超量展开、缺失或修改的文件。新目录在目标同卷暂存，准备失败时原程序继续运行。

辅助进程从应用目录外运行，等待主进程真正退出。Flutter 等待控制器结束网络、下载调度与数据库工作后，通过专门退出接口退出；关闭窗口隐藏到托盘不等于退出。辅助进程交换整个程序目录并重启。替换失败尝试恢复旧程序并弹出系统错误；恢复被外部文件占用等条件阻止时保留旧目录并给出人工恢复说明。

成功后清理本次下载 ZIP 与辅助程序自有文件。辅助进程在退出前可能无法删除作为当前工作目录的缓存目录，因而留下空的 GUID 目录；该残留不影响已经完成的程序替换、重启或用户媒体，仍需后续处理。0.8.0 发布时曾遇到测试清理根目录与辅助进程退出之间的时序竞争；0.9.5 的 Tag 工作流连续三次因此失败，未生成 Release，实际结果见 [0.9.5 发布记录](releases/0.9.5.md)。

0.9.6 的更新回归在旧测试进程仍存活时读取 `ready` 中的辅助进程 ID 并持有进程句柄；读取最多等待 5 秒，避免文件刚创建但尚未写完或关闭的竞争。确认安装完成后，最多等待 30 秒让辅助进程退出，并检查退出码为零，再清理测试目录。目录删除遇到短暂占用时每 100 毫秒重试，最多 5 秒；超时、非零退出码和永久清理错误仍导致测试失败，断言与清理同时失败时两者均保留。整体通过提示在清理完成后输出。本次只修正测试的同步与清理，不改变生产更新流程，也不声称解决空缓存目录残留；修复后的 Windows 分支 CI 与 Tag CI 均通过，0.9.6 已发布，实际执行结果见 [0.9.6 发布记录](releases/0.9.6.md)。

程序目录恢复不等于跨版本数据回滚；不保证新版本已经写入的数据库仍可被旧版读取。也不将“新进程启动成功”当作完整功能健康检查。

### macOS

`ReleasePage` 只接受官方仓库的具体版本 HTTPS 页面，使用 `NSWorkspace` 打开默认浏览器。本次不引入 Sparkle，不改变沙盒、签名或公证方式，也不自动替换 App。

### Linux

1.0.0 源码中 `UpdateTarget.linux` 与 macOS 一样属于打开 Release 页面的目标。`tamayura/updates` 通道只实现 `openRelease`：原生层用正则核对官方仓库具体版本的 HTTPS 页面地址，再通过 GIO 交给默认浏览器；没有可用浏览器时返回错误并可重试，其他方法返回未实现。用户自行下载对应架构的 tar.gz，退出旧版本后解压到新目录并重新运行 `install-desktop-entry.sh`。应用不替换自身目录，不请求 root 权限，也不处理发行版软件包。

## 任务与数据

更新会中断共享和传输；保留媒体文件、下载记录与分片的既有语义。进程重启后，中断任务沿用当前恢复机制，可由用户重试，不承诺安装后自动无缝续传。

1.0.0 建立媒体库 schema 7、下载任务库 schema 3、分钟配置与协议 v4 的正式版基线。本版不改动这些结构；后续升级须保留有效配置、设备记录、离线缓存、下载任务及文件，数据库或协议变更按 [兼容与升级](兼容与升级.md) 提供升级路径和兼容测试。更新 UI 仍提醒用户阅读 Release 说明；不支持的结构应保留原数据并明确报错，不能自动清库或用卸载重装代替常规升级。

## 测试与验收

- Flutter：更新服务覆盖排除预发布与草稿、正式版本排序、分页、损坏清单/附件、网络错误、允许的重定向、流式下载、超时、取消、完整性和并发限制；界面覆盖确认/拒绝、macOS 浏览器、Android 权限与失败重试、Windows 准备/退出顺序和窄屏大字体。
- Android：原生回归覆盖实际下载目录布局、路径与哈希、包名/版本/签名、安装来源授权、会话结果和中断。
- macOS：原生回归覆盖具体版本页面、拒绝其他地址、浏览器打开失败；同时保留现有原生回归。
- Windows：原生入口增加 PowerShell 更新流程回归，包括 ZIP 安全、文件完整性、版本、等待进程退出、目录替换和失败恢复；非 Windows 主机的源码检查不等于执行 Windows 更新。

0.8.0 已执行的本地与 CI 检查见 [版本记录](releases/0.8.0.md)，Windows 原生运行和打包由 Windows CI 完成。实际系统安装弹窗、厂商 Android 安装限制、Windows 用户环境中的文件占用和权限、系统策略及真正跨版本安装仍需真机验证；自动化测试不能替代正常应用的 GUI 与跨设备验收。
