# 发布与打包

当前统一版本为 **0.5.0+8**。Android、macOS 和 Windows 均从根目录 `pubspec.yaml` 读取版本：Android versionName `0.5.0` / versionCode `8`，macOS CFBundleShortVersionString `0.5.0` / CFBundleVersion `8`，Windows 数字文件版本 `0.5.0.8`。

0.5.0 的 Android、macOS 与 Windows 本地试用包已完成构建和核验，实际产物与检查结果见 [0.5.0 发布记录](releases/0.5.0.md)。当前发布目标包括 Android 通用 APK、macOS Universal ZIP 和 Windows x64 ZIP；三个平台的可执行产物全部构建、验证后，才可标记全平台交付完成。Windows 源码交接 ZIP 只是构建输入，不能代替 Windows 可执行包。历史 `dist/0.0.1` 至 `dist/0.4.0` 及对应版本说明保留原样。

## 版本与发布记录

1. 日常改动记在 `CHANGELOG.md` 的 `## unstaged`，分类记录功能、改进、修复和限制。
2. 发布时更新 `pubspec.yaml`。0.5.0 使用 `0.5.0+8`，构建号从 0.4.0 的 7 递增为 8；三个平台共用该版本。
3. 将本次变更放入 `## 0.5.0`，记录真实日期、交付状态和已知限制，前面保留空的 `## unstaged`。
4. 更新 README、新增 `docs/releases/0.5.0.md`；构建仍在等待时明确写“待构建”，不将源码检查、历史结果或未执行的 CI 写成通过。
5. 在 `dist/0.5.0/` 保存产物、公开签名核验记录、`SHA256SUMS` 和 `release.json`，逐项核对版本、字节数及 SHA-256。

发布文档、验证记录、日志和产物说明不得记录开发、打包或测试环境的内网地址、机器名、登录账号、SSH 连接信息、个人目录路径、密钥及凭据；只保留必要的通用工具链要求和脱敏结果。临时执行日志不得直接复制为公开发布记录。编译器可能把源码绝对路径写入可执行文件；发行包应从不含个人信息的通用临时源码目录构建，完成后扫描归档及解压内容中的环境隐私标记，再生成最终校验和。

现有交付方式为本地试用包。Git tag、远端 Release 和应用商店发布须有明确的目标仓库或渠道；本地生成安装包不等于已经上传。试用包需全部适用的自动化检查通过，并记录未完成的真机验收。正式公开发布前还需真实跨设备验收、干净环境重建，以及平台要求的公开分发签名。

## 统一工具链与检查

使用正式 **Flutter 3.47.6 stable / Dart 3.13.5**，依赖由 `pubspec.lock` 固定。先检查 `flutter --version`，依赖解析与后续构建使用同一 SDK。macOS 使用 Swift Package Manager，不混用另一份 Flutter checkout 生成的 `package_config.json`。

```sh
FLUTTER_SWIFT_PACKAGE_MANAGER=true flutter pub get
dart format --output=none --set-exit-if-changed lib test
flutter analyze --no-pub
flutter test --no-pub --coverage
```

离线且依赖缓存齐全时可用 `flutter pub get --offline`。完成一次一致源码和依赖下的公共检查后，可由不同平台构建任务复用结果；各平台的原生测试、Release 构建和产物核验仍须执行。独立调用打包脚本时，脚本会自行执行完整检查。

## Android

最低 Android 16（API 36），不支持 Android 15 及更早版本。需要 Android SDK / Build Tools 36、JDK 21；源码编译目标为 Java 17。Robolectric API 36 测试需 Java 21 或更新版本。如 Gradle 与测试使用不同版本 JDK，可通过临时 Gradle init 脚本指定测试 JVM；发布记录仅保留版本和测试结果，不记录个人安装路径。

```sh
(cd android && ./gradlew testDebugUnitTest)
flutter build apk --release --no-pub
mkdir -p dist/0.5.0
cp build/app/outputs/flutter-apk/app-release.apk dist/0.5.0/Tamayura-0.5.0-android.apk
apksigner verify --verbose --print-certs dist/0.5.0/Tamayura-0.5.0-android.apk
aapt dump badging dist/0.5.0/Tamayura-0.5.0-android.apk
zipalign -c -P 16 -v 4 dist/0.5.0/Tamayura-0.5.0-android.apk
```

确认应用 ID `dev.tamayura.app`、versionName `0.5.0`、versionCode `8`、minSdk / targetSdk `36`，通用 APK 包含 arm64-v8a / armeabi-v7a / x86_64。确认不可调试、release 验签通过，证书与既有本地试用版一致。

沿用专用本地 release 密钥：`android/keystore/tamayura-release.jks`（PKCS12，别名 `tamayura-release`，RSA 3072），由 `android/key.properties` 配置。`storeFile` 相对 `android/app` 解析，现有值指向 `../keystore/tamayura-release.jks`。密钥与配置权限为 `0600`，目录为 `0700`；不得打印密码、提交或复制到分发目录。缺少 release 签名配置时不得回退到 debug 签名。公开证书指纹可记录在验证文件中，私钥和密码不可分发。

如需按 ABI 拆分或商店包，可另外执行 `flutter build apk --release --split-per-abi` 或 `flutter build appbundle --release`；本次本地交付为通用 APK，生成 AAB 不代表已经上架。

## macOS

最低 **Sequoia 15.0**，支持 Tahoe 26 及后续版本。需要完整 Xcode 和 macOS SDK；仅 Command Line Tools 无法完成构建。插件使用 Swift Package Manager。

```sh
scripts/package-macos.sh
```

脚本执行公共检查、`scripts/test-macos-native.sh`、`flutter build macos --release --no-pub`，随后核验版本、最低系统、Universal 架构和签名，生成 `dist/0.5.0/Tamayura-0.5.0-macos.zip` 与 `SHA256SUMS-macos`。它不会覆盖其他平台的联合校验文件。

脚本兼容 macOS 自带的 Bash 3.2。中文提示中紧邻标点的变量使用 `${name}` 明确边界，避免 UTF-8 环境将标点字节误读为变量名，导致打包成功后仍以 `unbound variable` 失败，或掩盖版本校验的原始报错。

默认使用 `lib/main.dart` 正常入口与 `dev.tamayura.app` Bundle ID。原生 RunnerTests 如使用独立 Bundle、空 Dart 入口和隔离 DerivedData，只能记为原生宿主测试；正式 Release 必须重新使用正常入口构建，不能将测试宿主归档为应用。

本地 ad-hoc 打包还需去除主程序的原生调试符号（`strip -S`），避免插件缓存路径进入发行包，再按项目 `Release.entitlements` 重新 ad-hoc 签名；该流程须拒绝非 ad-hoc 输入，避免覆盖 Developer ID 等既有签名。公开签名发行应使用对应的独立签名与公证流程。

核验主程序、App.framework 与 FlutterMacOS.framework 含 arm64 / x86_64；检查 CFBundle 版本、最低系统 15.0、`codesign --verify --deep --strict`、ZIP CRC，并在解压副本上再次核验签名、版本和架构。`xcode-select` 指向 Command Line Tools 时，脚本自动为当前进程选用标准 `/Applications/Xcode.app/Contents/Developer`，不修改全局设置；非标准位置可传 `DEVELOPER_DIR`。

当前为 ad-hoc 本地签名、未公证。正式公开分发还需拥有者的 Developer ID、Hardened Runtime、签名与公证；ZIP 本身不是公证版本或 App Store 发布。详情见 [macOS 实现与验收](macOS原型.md)。

## Windows

目标为 Windows 10 1809+ / Windows 11 x64。必须使用 Windows 构建环境，并安装 Flutter 3.47.6、Visual Studio 2022 的“使用 C++ 的桌面开发”、Windows SDK 与 CMake。

也可使用 Visual Studio 2022 Build Tools：安装 `Microsoft.VisualStudio.Workload.VCTools`、`Microsoft.VisualStudio.Component.VC.Tools.x86.x64`、`Microsoft.VisualStudio.Component.VC.CMake.Project` 和 `Microsoft.VisualStudio.Component.Windows11SDK.26100`。可使用 Build Tools 17.14、MSVC 19.44 和 Windows SDK 10.0.26100.0；不需要 Android SDK 或 JDK。Flutter SDK、Git 和项目可以放在独立任务目录，仅为当前构建进程设置 PATH。工具链安装后先运行 `flutter precache --windows`，首次解析使用 `flutter pub get --enforce-lockfile` 并核对构建后的锁文件。

```powershell
flutter doctor -v
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1
```

脚本要求 x64 Windows 构建主机，执行格式、分析、Flutter 全量测试、Windows 原生 CTest 和 x64 Release 构建，核对 EXE 数字版本 `0.5.0.8`，将完整 `build/windows/x64/runner/Release` 归档为 `dist/0.5.0/Tamayura-0.5.0-windows-x64.zip`，并生成 `SHA256SUMS-windows`。Flutter 3.47.6 通过主机架构选择 Windows 目标，不接受 `build windows --target-platform`。任何检查失败都会终止。SQLite 原生资产、插件 DLL、Flutter 引擎和 `data` 必须随包保留，不能只发送 EXE。

`.github/workflows/windows.yml` 使用 `windows-2022` 执行同一流程并上传构建产物。使用前需有可访问的远端仓库；配置文件存在不代表 CI 已运行或产物已生成。

Windows 发行目录不包含 Flutter 测试专用的根 `native_assets.json`（其中含构建机绝对路径）；正式运行清单 `data/flutter_assets/NativeAssetsManifest.json` 和包根 `sqlite3.dll` 必须保留。CMake 同时排除新复制与清理旧构建残留，打包脚本显式核验这两个条件。解压后的启动检查需确认进程实际加载解压目录的 SQLite，避免构建机缓存掩盖缺失依赖。

Mac 可执行下列命令制作构建输入：

```sh
python3 scripts/test-windows-source.py
python3 scripts/package-windows-source.py
```

产物 `Tamayura-0.5.0-windows-source.zip` 和 `SHA256SUMS-windows-source` 使用源码白名单，排除其他平台原生工程、密钥、本机 SDK 配置、构建缓存和用户媒体。它不能作为 Windows 可执行发行包。Windows ZIP 当前为未签名试用包，无安装器、MSIX 或 Store 发布，需要相应 Visual C++ x64 运行库；首次联网只对可信专用网络授权防火墙。详情见 [Windows 实现与调试](Windows原型.md)。

## 统一校验与发布元数据

各平台完成后，对实际交付的可执行包生成 `SHA256SUMS`；在 Windows 未完成时只列出现有包，并在 `release.json` 明确整体状态为未完成。三个平台全部就绪后，可执行：

```sh
cd dist/0.5.0
shasum -a 256 Tamayura-0.5.0-android.apk Tamayura-0.5.0-macos.zip Tamayura-0.5.0-windows-x64.zip > SHA256SUMS
shasum -a 256 -c SHA256SUMS
```

Linux 可用 `sha256sum`。`release.json` 记录统一版本、构建号、日期、每个平台状态、最低系统、架构、产物文件名、字节数、SHA-256、签名和实际验证结果；元数据、版本说明与目录文件保持一致。源码辅助包使用独立校验文件，不能混作已交付的可执行平台。

## 安装、数据与验收

0.5.0 保持协议 v3，媒体库升至 schema 5，下载任务库升至 schema 3，旧库直接清空重建。媒体库重建会清空设置、记住的设备、离线相册与缩略图、下载历史索引；下载任务库重建会清空任务列表，旧的未完成分片由启动清理回收。需要重新选择目录并发现设备。v1.0.0 前不承诺不同应用版本或旧数据兼容，不增加历史迁移、旧协议适配或回退逻辑。允许覆盖安装；遇到不兼容可以清空应用数据或卸载重装，再重新选择目录、发现设备。外部原始媒体和已保存的接收文件保留。

同签名 Android release 可执行 `adb install -r dist/0.5.0/Tamayura-0.5.0-android.apk`。debug 与 release 证书不同，签名冲突时需先卸载；卸载会清除设置、SAF 授权、缓存、下载记录及未完成分片。macOS 完整解压 ZIP，将 App 放入“应用程序”；本地未公证包若被系统拦截，在确认来源和校验后通过系统“隐私与安全性”确认，不关闭全局 Gatekeeper。Windows 完整解压 ZIP 后运行 EXE。

互联设备使用相同版本。在真实 Android 16+、macOS 15.0+、Windows 目标系统完成自动发现、目录权限、离线缓存、小照片与大视频、取消续传、断网/睡眠恢复、后台共享和文件完整性验收。扫码与系统分享仅按各平台支持范围验收。Sequoia/Intel、厂商 Android 电源策略和 Windows 防火墙/运行库仍需真实环境验证，自动化不能替代。

发布清单：公共与适用平台测试通过；Release 包版本、签名、架构、最低系统、校验和正确；试用性质及未完成验收清晰；分发目录不含密钥、密码、绝对 SDK 配置或用户照片。正式公开发布前还需干净环境或 CI 重建。
