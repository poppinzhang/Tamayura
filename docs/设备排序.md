# 已保存设备排序

## 使用方式

设备页的「已记住的设备」区域在至少有两台设备时显示「调整顺序」。打开后可拖动手柄，也可使用上移、下移按钮调整位置；点击「保存」后，设备列表和相册顶部的设备筛选栏立即使用相同顺序。取消不会改变已保存的顺序。

在线和离线设备都可以排序。顺序按设备 ID 保存，同名设备分别处理；设备改名、地址变化、重新发现及同步不会改变已保存的位置。重启后恢复顺序，相册当前选择的设备和合集不因排序改变。

## 数据与状态

- 使用媒体库现有 `settings` 表的 `deviceOrder` 键保存设备 ID 的 JSON 数组，无需改变数据库结构或网络协议。
- `AppController.devices` 是设备页和相册设备筛选栏共用的数据来源，先按已保存的位置排序，尚未排序的设备放在末尾并按名称、ID 排序。未设置顺序时也按名称、ID 排序。
- `reorderDevices` 过滤提交列表中的未知 ID 和重复 ID，再追加当前已知但未包含的设备，避免排序对话框打开期间发现的新设备丢失。保存过程中发现的设备仍显示在已排序设备之后，可在下次排序时安排位置。
- 排序是当前设备的本地偏好，不通过 gRPC 发送到其他设备。持久化成功后才发布新顺序；存储失败保留原顺序并提示重试。保存期间禁止重复提交，对话框保留草稿并在失败后允许再次保存。
- 设置内容损坏或不是字符串数组时使用默认顺序，避免阻塞启动；再次保存会写入有效设置。用户自行清空应用数据会同时清空排序；正式版正常升级须保留有效排序，遵循 [兼容与升级](兼容与升级.md)。

## 验证

自动化覆盖控制器持久化与重新打开、同名设备、无效设置、写入失败与重试、保存并发、设备更新及新增；界面测试覆盖移动端和桌面操作、拖动与按钮排序、取消、保存中状态、失败重试，以及设备页与相册顺序一致。
