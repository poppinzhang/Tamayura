# 下载存储与暂存清理

## 分片直接保存

下载仍按现有范围分片，超过 50 MiB 使用四路并发；每片文件长度是持久续传游标。`downloadResumable` 返回已验证顺序及长度的 `DownloadParts`，正式任务不再生成 `complete.partial`。

平台 `saveDownload(sourcePaths, expectedSize, ...)` 顺序读取私有目录分片，直接写入接收目录，仅使用有限缓冲区；保存前和写入后都核对总大小，不覆盖已有文件。正常情况下同时存在 S 字节分片和至多 S 字节目标，故同卷峰值约 2S，异卷分别约 S。保存失败尝试删除目标半成品，保留分片；完整分片的签名和长度校验通过后，重试保存不再要求来源设备在线。

Linux 在创建接收子目录前检查完整目标绝对路径，包括接收根、设备名、合集名、相对目录和文件名，限制为 4095 个 UTF-8 字节；同名文件追加序号后也必须满足此限制。超限以 `PATH_TOO_LONG` 返回可见错误，任务失败且保留完整分片，不写入完成记录。选择较短的接收路径后可离线重试保存。匿名文件与独占创建两种保存方式使用同一检查，具体边界见 [Linux 实现](Linux原型.md)。

`MediaDownloader.download()` 是独立辅助入口，可以将分片写入它自己的最终文件；UI、后台服务和桌面调度器使用分片直存路径。

## 暂停、删除和恢复

- 「暂停下载」停止调度及当前工作，保留分片，之后「继续下载」仍复用同一任务。内部 `cancelled` 状态用于这一暂停语义。
- 「取消并删除」或「删除任务并释放空间」先持久化 `discarded` 状态并撤销 run token，阻止旧 worker 写状态及新调度接管，再等待旧 worker 和 native 保存释放文件，最后删除私有暂存目录及任务记录。
- 删除失败保留可重试标记。进程中断后，初始化会停止仍在调度的待删除任务，并补清待删除、已完成残留和没有任务记录的孤立目录。暂停、失败、排队和运行任务不按时间自动删除。
- 未完成任务不受最近 100 条完成历史的显示限制，始终可以找到并释放空间。界面以持久进度显示约已暂存字节。
- 删除任务只处理应用私有暂存。如果保存刚好成功，持久下载 URI 和接收文件保留，界面仍显示已保存；完成记录离开最近任务窗口也不会丢失完成标记。

Android 的 `cancelTransfer` 响应等待旧 FlutterEngine 和 native I/O 全部结束；桌面取消等待 runner 结束。这是删除文件之前必须满足的条件，单独取消系统调度不足以证明文件已经释放。

已保存的接收文件通过相册或预览页的「删除本地文件」单独删除。该操作删除接收文件及保存记录，保留对端媒体元数据和缩略图，与上面的「删除任务并释放空间」处理对象不同。交互、平台文件访问与异常处理见 [本地媒体删除](本地媒体删除.md)。

## 空间检查

`transferSpace(directoryUri)` 返回暂存与目标的可用字节数，以及是否同卷。下载前和导出前分别检查，并预留 16 MiB 余量。暂存已有 R 字节、文件总大小 S 时，同卷后续约需 `2S - R`；异卷暂存约需 `S - R`、目标约需 S。计算使用有效分片实际长度，不信任过期进度字段。

macOS、Windows 与 Linux（1.0.0 源码，`fstatvfs` 与设备号判断同卷）查询实际卷；Android 至少报告私有暂存容量，SAF 提供者不能可靠报告目标容量时字段为空。未知容量不视为零。预检无法阻止其它任务或应用随后耗尽空间，因此所有实际读写错误仍须处理，不能仅凭预检标记成功。

## 版本与边界

1.0.0 使用媒体库 schema 7、下载任务库 schema 3 与传输协议 v4；升级不清空设置、设备、相册、下载历史或任务。0.5.0 引入媒体库 schema 5 时的重建属于历史安装影响，见 [0.5.0 版本记录](releases/0.5.0.md)。后续正式版变更遵循 [兼容与升级](兼容与升级.md)，外部原始文件与已保存的文件不会因暂存清理而删除。

目标提供者与 SQLite 之间没有跨系统事务：进程在保存成功、记录 URI 之前被强制结束时，目标可能留下未登记文件，重试可能另存同名副本。系统强杀也可能绕过目标半成品清理。普通异常和协作取消有清理，不能将其等同于强杀保证。

## 验证

回归覆盖大文件分片顺序与总量、没有第三份完整暂存、失败续传、离线重试保存、同卷/异卷/未知容量、导出前二次预检、暂停与删除独立操作、旧 worker 写入隔离、等待保存退出、完成 URI 保留、启动清理及超过历史窗口的未完成任务。

Linux 原生保存回归还覆盖深层路径、ASCII 与多字节名称的完整路径边界、同名后缀越界、两种保存方式失败时分片保留及成功结果可读取和删除。`test/transfer_test.dart` 验证 `PATH_TOO_LONG` 与权限失败均不登记完成，并可复用分片离线重试。

相关入口：`test/transfer_test.dart`、`test/resumable_download_test.dart`、`test/transfer_cleanup_test.dart`、`test/transfer_controls_cleanup_test.dart`、`test/transfer_controller_cleanup_test.dart`、`linux/tests/storage_test.cc` 和各平台保存/桥接测试。Linux 本轮验证范围记录于 [Linux 实现](Linux原型.md)。
