# Android 原型实现

## 使用场景与设备范围

A 手机需要 B 手机上的照片：双方在同一局域网打开 Tamayura，B 授权相机目录，A 浏览已缓存的缩略图，点击下载原文件到指定目录，再预览或分享。照片、视频的原文件只在用户下载时传输。

本轮仅支持 **Android 16 / API 36 及以上**，`minSdk`、`targetSdk`、`compileSdk` 均为 36。界面、数据库与 gRPC 使用 Flutter/Dart，目录访问、NSD 和系统下载调度通过 Android 适配器实现。

## 发现与身份

本机身份由系统 `Settings.Secure.ANDROID_ID` 派生为 `android-<小写十六进制值>`，启动时通过 `AndroidBridge.deviceId()` 读取，不在 SQLite 中保存或生成设备 UUID。系统标识不可用时显示错误，刷新可重试，不广播随机替代身份。设备名优先读取系统设备名称，缺失时使用厂商与机型；ID 用于内部识别，设备列表和相册显示名称。同一 ID 的名称及地址变化更新原记录，同名不同 ID 仍是不同设备。详见 [设备身份与记忆](设备身份与记忆.md)。

默认服务端口为 50728，端口占用时使用动态端口并广播实际值。NSD 服务类型为 `_tamayura._tcp.`。二维码格式仍为 `tamayura://192.168.1.8:50728?v=1`；此处 `v=1` 是二维码格式版本，独立于传输协议版本。端口寓意见 [关于与项目缘起](关于与项目缘起.md)。

原型限定私有 IPv4 局域网。发现、手动输入地址和扫码都先通过 `GetIdentity` 核对稳定设备 ID；记忆地址被 DHCP 分配给另一台设备时不会误用其目录或文件。新的发现地址在当前连接结束后继续处理，避免因旧地址连接尚未超时而丢失。

启动先提供本地缓存；随后在发现设备、返回前台或用户刷新时尝试同步。来源手机也需要完成本地扫描，接收方才能获取其新增和删除。当前不进行实时文件监听或后台目录轮询。提供原文件的一端仍需保持应用可连通；接收端下载可由独立系统任务继续。

## v3 多目录、大相册分页与增量缓存

`GetIdentity.protocol_version` 为 **3**，双方需使用相同当前协议。服务路径为 `tamayura.v1.MediaLibrary`，不适配旧协议。

协议层只依赖纯 Dart 的 `CatalogRepository` 接口，不直接导入 sqflite/Flutter。Android 的 `TamayuraRepository` 实现该接口，命令行测试对端可直接通过 Dart SDK 启动。

1. `LocalMediaSource.scan()` 只返回 `MediaMetadata`：ID、名称、MIME、大小、修改时间、共享目录标识/名称和根下相对路径。Android 的 `scanDirectoriesMetadata` 递归读取 SAF 元数据，不生成或集中存放缩略图。移除原有媒体总数和累计缩略图预算限制；服务端内存保存轻量索引，不保存整本相册的缩略图。
2. `ListMediaPage` 默认每页 200 项，最多 500 项。每次成功扫描以确定性的元数据摘要发布 revision，内容没有变化时跨进程重启也保持 revision。分页 token 绑定 revision，目录变化后旧 token 返回 `ABORTED`。客户端重新核对分页并复用已收到的匹配缩略图，默认最多额外重试两次。
3. 元数据页不携带图片字节。`GetThumbnail` 按媒体 ID 与 revision 单独请求，单张限制 512 KiB。服务端最多同时执行四个缩略图生成操作，返回前再次检查 revision，防止跨目录版本混用。
4. 客户端先比较已缓存或未完成快照的 revision。完整相册没有变化时无需接收目录和缩略图；未完成快照则补齐缺失缩略图、从下一页继续。revision 改变时逐页比较本地元数据，复用正式库与未完成快照中未变化项目的 SQLite 缩略图，只获取新增或元数据变化项目的缩略图。
5. 同步内存只保留当前元数据页及最多四张正在接收的缩略图。每张缩略图立即写入独立图片表，暂存元数据引用该图片并逐步显示；未收到缩略图的新增项尚不展示，旧相册仍可浏览。收到完整目录、所有必需缩略图且数量验证通过后，SQLite 在一个事务中发布新增/变更并删除已移除项。断网、缩略图错误、扫描撤权和进程退出保留已就绪预览与分页断点；无效协议数据丢弃当前不可恢复会话，原离线缓存保持不变。相册按设备显示已就绪数量、同步进度及继续同步入口，详见 [同步进度](同步进度.md)。

媒体数据库当前 schema 为 5，下载任务库为 3；不兼容的旧库清空重建，不进行历史版本数据迁移。并发快照用 generation 校验，较早的同步不能覆盖较新的提交。UI 与独立下载引擎使用各自的 SQLite 连接、WAL 与 5 秒锁等待；打开新连接恢复最新有效断点，不按时间删除；重试轮换会话 ID，阻止旧请求覆盖新任务。

相册首页按设备和共享根聚合合集；进入合集后通过 `listMediaPage` 同时按设备与共享根筛选，读取游标页，默认 60 项、上限 200 项，按修改时间、设备 ID 和媒体 ID 排序。游标避免加载所有缩略图；切换设备或合集后重新读取首页，同步过程中合并刷新并保留已经加载的浏览页数。下载记录独立于远端目录删除，已经保存到手机的副本不会被删除。

初次同步仍需逐步生成并缓存所选目录的缩略图；索引内存、缓存磁盘与首次耗时随相册规模增长。分页解决集中载入大量图片的问题，不代表扫描和完整首轮同步没有成本。

## 目录授权与原文件边界

目录选择使用 `ACTION_OPEN_DOCUMENT_TREE` 和持久 URI 授权。支持多个互不重叠的共享目录，只扫描图片/视频，递归子目录；同目录和任意添加顺序的父子重叠都会拒绝。详见 [多目录共享与合集](多目录共享与合集.md)。本地 URI 不进入网络协议，远端只得到稳定的不透明媒体 ID。重新扫描期间保留旧文件映射继续服务，扫描成功后整体替换；移除目录、扫描失败或授权失效会撤销映射，单个无法读取的文件或子目录只被跳过；共享目录不可用时目录 RPC 返回失败，不用“空目录”误删对端缓存。

`ReadFile` 仅接受当前共享快照中的媒体 ID、offset 和 length。每块最多 2 MiB（`mediaReadChunkBytes`，见 [传输恢复](传输恢复.md#分块大小)），验证请求范围与实际读取长度。文件内容修改不在同步范围内；大小改变、提前结束或不连续的字节范围会拒绝传输。

## 独立系统下载与恢复

用户从可见界面发起下载时，应用先持久化任务，再提交 Android **user-initiated data transfer（UIDT）JobScheduler** 任务，不请求或等待通知权限。原生 `BackgroundTransferService` 启动自己的 FlutterEngine 和 Dart 入口，下载不依赖 `MainActivity` 的生命周期。通知允许时显示进度和结果；未授予通知权限、关闭应用通知或下载频道时仍正常下载，在应用内查看进度。UIDT 仍按系统要求关联通知，由系统控制是否展示；详细约束见 [后台下载实现](android-storage.md#uidt-后台下载)。任务只要求 Wi-Fi/以太网可用，不要求局域网具有互联网连通性。

下载任务包含排队、接收、保存、完成、失败或取消状态。任务归属令牌与原生运行门控防止旧引擎覆盖新一轮任务，下载中心从持久记录恢复进度。系统可以停止或重新调度任务；来源手机暂时不可达时自动重试最长 30 分钟；用户强行停止整个应用或来源长时间不可达时，需要再次打开应用重试，不保证永久后台运行。详见 [传输恢复](传输恢复.md)。

来源端现可通过「设置 → 后台共享」启用 `connectedDevice` 前台服务。主引擎、媒体读取和 NSD 独立于 Activity，锁屏后继续响应；关闭时释放后台资源，退后台停止共享监听及在途请求。实现、电池限制与验收见 [后台共享](后台共享.md)。

文件严格大于 50 MiB 时使用四个并发 gRPC 范围，等于阈值时使用单路。分片写入应用私有持久目录，manifest 记录设备/媒体 ID、大小和修改时间。重试从各分片已经落盘的长度继续，只请求尚缺字节；元数据不匹配或分片超长时重建对应暂存数据。断网、系统停止和失败时保留可恢复分片，成功导出并记录 URI 后清理。

所有分片完成后顺序拼接并核验总大小，再经 SAF 导出到用户选择的接收目录下，按照「设备 / 共享根 / 原有子目录」保留层级。目标目录映射持久化以区分同名来源，并供独立后台引擎使用。命名剥离路径和非法字符，避免覆盖现有副本。SAF 导出失败会删除未完成的目标文档；任务显示错误供重试。当前不计算内容哈希，也不处理同大小的原件内容修改。

## 预览与分享

下载前可放大查看缓存缩略图；已下载图片从本地 URI 生成最大 2560 像素的预览，避免直接解码超大原图。视频通过系统兼容应用打开，也可使用 Android 分享面板。外部删除文件或撤销权限后，打开/分享会先验证可读性，失效记录会被清除以允许重新下载。

## Android 16+ 双机验收清单

以下应在两台 Android 16/API 36 或更高版本真机上验收，loopback 测试和模拟器不能替代：

1. 同 Wi-Fi 自动发现、手动 IPv4 与扫码；重启后立即浏览离线缓存，DHCP 换地址后恢复连接。
2. 共享超过 2000 项的照片/视频目录，滚动加载各页，切换设备后没有重复或遗漏；取消授权后旧文件不可读取。
3. 完成首轮同步后再次刷新，无变化时没有缩略图重传；新增/删除后只传必要缩略图，已保存副本保留。
4. 在目录分页或缩略图接收过程中改变来源目录、断网或撤权，旧缓存保持完整；网络恢复后重试成功。
5. 点击下载小图片和大于 50 MiB 的视频，切换应用、锁屏、重建 Activity，观察实际文件进度；允许通知时显示独立任务通知。
6. 下载中断开 Wi-Fi、停止来源或使系统停止任务；恢复后从现存分片继续，而非重新下载全部内容。测试用户取消与重试竞争。
7. SAF 接收目录撤权、空间不足、重复名称、取消导出和外部删除均给出可恢复反馈，未完成目标文档不留作成功文件。
8. 图片放大预览、视频系统打开、分享至常用应用；首次未授予通知权限、拒绝通知、关闭应用通知或下载频道时均不弹授权请求且能完成下载、应用内进度正常，允许通知后恢复提醒。拒绝相机权限后仍有明确恢复入口。
9. 完成一个后台任务期间继续浏览和同步相册，UI 数据库连接保持可用；系统强行停止应用后重新启动可以恢复任务记录。

局域网无鉴权、无 TLS、IPv6、跨设备去重和文件内容编辑同步仍不在当前范围内。后台目录扫描和来源端常驻共享也尚未实现。
