# 单张缩略图容错

共享目录扫描与实际缩略图读取之间，文件可能已被删除或发生变化，也可能无法解码。缩略图失败分为两类：只影响这一个文件、重试也不会改变结果的，记为空缩略图，让其余目录同步完成；可能恢复的权限、目录或资源故障继续报错，由接收端保留断点稍后重试，不缓存为空图。

## 来源端

各平台原生层在目录授权和共享目录生命周期检查内生成缩略图，对单个文件的以下情况返回空字节：

| 平台 | 返回空缩略图 | 仍然报错 |
|---|---|---|
| Android | 除授权失效外的所有生成失败（`loadThumbnail`、`ImageDecoder`、视频关键帧） | `SecurityException`、文件不在当前目录、目录变化 |
| macOS | 文件缺失（`ENOENT` / `ENOTDIR`）、大小变化、无法解码、AVFoundation 错误 | 共享目录授权或根目录不可用、权限、磁盘或配额不足、文件描述符耗尽及其他 I/O 故障、目录变化 |
| Windows | 文件缺失、大小或修改时间变化、WIC / Shell 无法生成预览（`PREVIEW_FAILED`） | 共享目录无法打开、共享冲突、权限及其他 I/O 故障、文件不在当前目录、目录变化 |
| Linux（1.0.0 源码） | 文件缺失、大小或修改时间变化、GdkPixbuf 与系统缩略图程序均无法生成预览或超时（`PREVIEW_FAILED`） | 共享目录无法打开、权限、符号链接、内存及其他 I/O 故障、文件不在当前目录、目录变化 |

Windows、Linux 的 `MediaCatalog::Thumbnail` 与 macOS 的 `MediaCatalog.thumbnail` 结构相同：先查找发布记录、固定共享根目录（失败直接报错），再在容错范围内打开文件、比较扫描时的大小和修改时间并生成预览，前后两次校验目录生命周期。正常下载仍使用严格的 `WithMedia` / `withMedia`，不会把缺失或变化文件视为成功。

Linux 同样在每次请求时重新打开文件并比较大小与修改时间，之后才使用来源端有容量上限的内存缓存；同一未变化文件的并发请求共享一次生成，撤销共享或重新扫描后迟到的结果不会写回缓存，实现见 [Linux 实现](Linux原型.md)。

当前未发布源码在 Windows 的这些检查之后复用来源端内存缓存。缓存命中不会跳过文件状态与权限验证；确定无法解码的空图可缓存，权限、共享冲突和 I/O 错误不缓存。RAW 内嵌预览失败会先尝试其它候选和完整帧，全部不可用才返回空图，详见 [Windows 缩略图](Windows缩略图.md)。

Dart 服务端（`_MediaService.getThumbnail`）按以下规则转换为 gRPC 状态：

- 来源返回的字节超过 512 KiB：`NOT_FOUND`。该文件重试也不会得到可用预览。
- 来源抛出异常：先重新校验目录版本，期间目录已变化或扫描失败时返回 `ABORTED` / `FAILED_PRECONDITION`；否则返回 `UNAVAILABLE`。
- 请求的媒体不在当前目录快照中：`NOT_FOUND`。

`LocalMediaSource.readThumbnail` 的约定是：单个文件没有预览时返回空字节，只为可恢复的故障抛出异常。

## 接收端

`MediaRpcClient.synchronize` 把缩略图的 `NOT_FOUND` 记为已完成的空缩略图并继续同步；其他错误（包括 `UNAVAILABLE`）保留断点并结束本次同步，不吞掉 RPC、断网和目录版本错误。空缩略图使用现有响应格式，界面显示占位图；元数据不变时后续同步复用这条记录，不重复请求。源端重新扫描后，已删除文件从目录快照移除，变化文件获得新的元数据并重新请求缩略图。

## 测试

- `macos/Tests/StorageCoreTests.swift`：文件删除、大小变化、损坏图像返回空图，权限、资源、I/O 与生命周期错误继续报错，下载语义保持严格。
- `windows/tests/storage_test.cpp`：同一组场景，另含被其他程序独占写入的文件、移走共享根目录及生成预览期间撤销目录。
- `test/network_test.dart`：超大缩略图以空图完成同步；来源抛出的失败返回 `UNAVAILABLE`，期间目录变化返回 `ABORTED`；接收端只把 `NOT_FOUND` 记为空图，其他错误保留断点。
- `test/mac_thumbnail_sync_test.dart`：通过本地真实 gRPC 验证断点恢复、空图缓存和下次扫描的删除同步。
