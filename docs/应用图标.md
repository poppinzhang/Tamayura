# 应用图标

## 统一原图

`assets/branding/app_icon.png` 是用户提供的 1254 × 1254 RGB PNG，保留原始文件内容，作为所有平台应用图标的共同来源。后续接入 iOS、macOS、Windows 和 Linux 时，从这张原图导出各平台所需的尺寸与格式。

这张图片用于平台应用图标，当前无需在 Flutter 界面中加载，因此不加入 `pubspec.yaml` 的运行时 assets 列表。

## 应用内与系统区域的小 Logo

1.0.0 源码使用用户提供的新版「響」（U+97FF）SVG，应用于应用顶部、关于页、macOS 菜单栏及 Linux 托盘。三个原文件 `hibiki-black.svg`、`hibiki-white.svg`、`hibiki-macos-cutout.svg` 逐字节保存在 `assets/branding/hibiki/source/`。它们与橙色平台应用图标分别维护；Windows 托盘、安装图标、Dock、窗口图标及应用菜单入口仍使用橙色原图，导航及操作按钮继续使用 Lucide。

应用内和 Linux 托盘在浅色外观下使用黑底白字，深色外观下使用白底黑字，使实底与界面背景形成反差、保留完整轮廓。直接保留 SVG 自带的圆角及外部透明区域，不二次裁剪、不重绘字形；macOS 使用专用的透明镂空版本，由系统渲染模板图像。

| 位置 | 资源与绘制 | 外观来源 |
| --- | --- | --- |
| Flutter 顶部 22.4 / 关于页 51.2 逻辑像素（边长缩小 20%） | `AppLogo` 加载 `assets/branding/hibiki/` 的黑、白两套 PNG；每套提供 64 / 128 / 256px，作为 1x / 2x / 4x 资源，不额外添加圆角裁剪 | 当前 `material_ui` 主题；手动选择与跟随系统均实时生效 |
| macOS 菜单栏 18pt | `StatusIcon` 图像集使用原始 `hibiki-macos-cutout.svg`，保留矢量表示并设置 `isTemplate`；字形及外部圆角区域均透明，系统只着色剩余轮廓 | AppKit 根据菜单栏外观自动着色，镂空字透出菜单栏背景；独立于 Flutter 手动主题 |
| Windows 托盘 | 复用 `windows/runner/resources/app_icon.ico` 的 `IDI_APP_ICON` 橙色资源，按系统小图标尺寸加载 | 保持原有配色，不随主题切换 |
| Linux 托盘 | `data/tray` 平铺保存黑、白两套 16 / 20 / 24 / 32 / 40 / 48 / 64px PNG，共 14 个文件；保留原始 alpha 转换为 StatusNotifierItem 的 ARGB32 像素，不叠加圆角遮罩，与橙色 hicolor 图标目录分开 | GTK 系统主题；主题改变后更新图像并发出 `NewIcon` |

素材字形来自 Nagino Medium，SVG 已将字形转换为路径，不依赖用户安装字体。来源说明及上游 SIL Open Font License 1.1 保存在 `assets/branding/hibiki/license/`，保留 Nagino 及其汉字来源 ZEN 丸ゴシック的版权声明；许可与应用一起离线打包，并由 `registerBrandingLicenses` 加入“关于 → 开源许可”。

生成脚本 `scripts/generate-branding-icons.cjs` 使用 Node.js 和 `sharp`，从黑、白原始 SVG 按目标尺寸直接渲染 Flutter 和 Linux PNG。生成结果随源码提交，普通构建无需安装 SVG 渲染工具；macOS 图像集直接保存专用 SVG，不经过 PNG 生成流程。

回归入口：`test/app_logo_test.dart` 检查三档密度资源、系统及手动主题切换、两种显示尺寸、实际渲染的原有圆角透明像素与黑白底色、离线许可；关于页测试检查 Logo 大小和布局。macOS 原生测试覆盖专用 SVG、模板标记、18pt 尺寸、透明镂空及资源缺失处理；Linux 原生测试检查 14 个 PNG 的尺寸、原始透明轮廓、反色字形与 D-Bus 图像更新通知。Windows 保留原有托盘行为及原生测试。

自动化检查不能替代真实菜单栏和托盘宿主的视觉验收。不同缩放比例下的字形辨识度、macOS 菜单栏自动着色及 Linux GTK 主题判断和回调仍需实际桌面验收，完整跨平台构建与发布核验按发布流程执行。

## Android 接入

- `android/app/src/main/res/drawable-nodpi/ic_launcher_artwork.png` 是原图的完整副本。使用 `nodpi` 保留像素，显示时由 bitmap drawable 等比填充正方形图标区域并开启滤波。
- `android/app/src/main/res/mipmap-anydpi/ic_launcher.xml` 定义自适应图标；清单的 `android:icon` 与 `android:roundIcon` 都引用它，由桌面决定最终轮廓。
- 前景四边各内缩 `16.666667%`，将原图放在自适应图层中央的 72/108 区域。原图已有的留白使整行文字位于安全区域内，避免直接铺满 108 × 108 图层造成文字边缘被裁切。使用比例内缩，使桌面、设置页和系统启动页等不同尺寸保持一致。
- 背景色 `#EB6532` 取自原图边缘的平均颜色，在桌面动画露出前景外围时补齐背景；正常静态显示区域由原图铺满。
- 仅支持 Android 16+（API 36），直接使用自适应图标，不增加旧系统图标或兼容分支。下载通知继续使用系统提供的下载状态小图标。
- 当前保留原图的橙白配色，没有另行设计单色图层；系统主题图标模式下的着色由桌面决定。

配置依据：[Android 自适应图标文档](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)。

## Linux 接入

1.0.0 源码的 Linux 图标位于 `linux/runner/resources/icons/<尺寸>.png`，共 16、22、24、32、48、64、128、256、512 九种尺寸，均由原图经 Lanczos 缩放导出为不含时间等元数据的 RGB PNG。CMake 安装时按 hicolor 图标主题布局放入发行目录 `data/icons/hicolor/<尺寸>x<尺寸>/apps/dev.tamayura.app.png`，文件名与 GTK 应用 ID 一致：

- 窗口图标：Runner 从可执行文件旁的 `data/icons` 读取 256 及以下尺寸，设为窗口图标列表，不依赖系统图标主题。
- 托盘图标：使用上述独立黑白「響」资源，转换为 StatusNotifierItem 要求的 ARGB32 像素随属性发送，托盘宿主无需读取文件。
- 应用菜单：`install-desktop-entry.sh` 将九种尺寸复制到当前用户的 `$XDG_DATA_HOME/icons/hicolor`，桌面入口以 `Icon=dev.tamayura.app` 引用，`StartupWMClass` 同为应用 ID，使运行中的窗口与菜单项对应。

## 更换原图与验证

将新原图保存到 `assets/branding/app_icon.png`，再从项目根目录同步 Android 副本：

```sh
cp assets/branding/app_icon.png android/app/src/main/res/drawable-nodpi/ic_launcher_artwork.png
cmp assets/branding/app_icon.png android/app/src/main/res/drawable-nodpi/ic_launcher_artwork.png
flutter build apk --debug
```

如果新图片的留白、背景或文字位置改变，需要重新检查安全区域，并调整内缩比例与背景色。

Linux 图标使用 ImageMagick 重新导出（ImageMagick 7 将 `convert` 换为 `magick`），`scripts/test-linux-native.sh` 会核对九个文件均为对应尺寸的 PNG：

```sh
for size in 16 22 24 32 48 64 128 256 512; do
  convert assets/branding/app_icon.png -filter Lanczos -resize "${size}x${size}" -strip \
    -define png:exclude-chunks=date,time "PNG24:linux/runner/resources/icons/$size.png"
done
```

安装到 Android 16+ 后，检查桌面、应用列表、系统应用详情和冷启动图标；分别检查圆形与圆角轮廓中四个假名是否完整。浅色与深色系统下均应保留原图内容。原始文件与 Android 副本应保持逐字节一致。

本次已通过原图及 Android 副本的逐字节校验、debug APK 构建，以及打包后 Manifest 和自适应图标资源检查。当前没有已连接的 Android 设备，尚未进行真机桌面视觉验收。
