# 应用图标

## 统一原图

`assets/branding/app_icon.png` 是用户提供的 1254 × 1254 RGB PNG，保留原始文件内容，作为所有平台应用图标的共同来源。后续接入 iOS、macOS、Windows 和 Linux 时，从这张原图导出各平台所需的尺寸与格式。

这张图片用于平台应用图标，当前无需在 Flutter 界面中加载，因此不加入 `pubspec.yaml` 的运行时 assets 列表。

## Android 接入

- `android/app/src/main/res/drawable-nodpi/ic_launcher_artwork.png` 是原图的完整副本。使用 `nodpi` 保留像素，显示时由 bitmap drawable 等比填充正方形图标区域并开启滤波。
- `android/app/src/main/res/mipmap-anydpi/ic_launcher.xml` 定义自适应图标；清单的 `android:icon` 与 `android:roundIcon` 都引用它，由桌面决定最终轮廓。
- 前景四边各内缩 `16.666667%`，将原图放在自适应图层中央的 72/108 区域。原图已有的留白使整行文字位于安全区域内，避免直接铺满 108 × 108 图层造成文字边缘被裁切。使用比例内缩，使桌面、设置页和系统启动页等不同尺寸保持一致。
- 背景色 `#EB6532` 取自原图边缘的平均颜色，在桌面动画露出前景外围时补齐背景；正常静态显示区域由原图铺满。
- 仅支持 Android 16+（API 36），直接使用自适应图标，不增加旧系统图标或兼容分支。下载通知继续使用系统提供的下载状态小图标。
- 当前保留原图的橙白配色，没有另行设计单色图层；系统主题图标模式下的着色由桌面决定。

配置依据：[Android 自适应图标文档](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)。

## 更换原图与验证

将新原图保存到 `assets/branding/app_icon.png`，再从项目根目录同步 Android 副本：

```sh
cp assets/branding/app_icon.png android/app/src/main/res/drawable-nodpi/ic_launcher_artwork.png
cmp assets/branding/app_icon.png android/app/src/main/res/drawable-nodpi/ic_launcher_artwork.png
flutter build apk --debug
```

如果新图片的留白、背景或文字位置改变，需要重新检查安全区域，并调整内缩比例与背景色。

安装到 Android 16+ 后，检查桌面、应用列表、系统应用详情和冷启动图标；分别检查圆形与圆角轮廓中四个假名是否完整。浅色与深色系统下均应保留原图内容。原始文件与 Android 副本应保持逐字节一致。

本次已通过原图及 Android 副本的逐字节校验、debug APK 构建，以及打包后 Manifest 和自适应图标资源检查。当前没有已连接的 Android 设备，尚未进行真机桌面视觉验收。
