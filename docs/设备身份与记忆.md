# Android 设备身份与记忆

## 身份与名称

Android 16+ 从 `Settings.Secure.getString(contentResolver, Settings.Secure.ANDROID_ID)` 读取本应用的系统标识，校验为 1–16 位十六进制字符串并规范为小写。对外设备 ID 为 `android-<ANDROID_ID>`；固定平台前缀满足现有 NSD ID 字符约束，并预留其他平台独立生成标识的空间。

`MainActivity` 的 `deviceId` 方法通过 `AndroidBridge.deviceId()` 提供给控制器。控制器在打开数据库及启动网络之前读取身份；不再读写 `settings.deviceId`，也不以随机 UUID 作为回退。读取异常、空值或非法值作为设备标识错误呈现，刷新会重新尝试。共享目录、下载任务和目录快照仍可使用各自的随机 ID，和设备身份无关。

`localInfo` 优先使用 `Settings.Global.DEVICE_NAME`；系统未提供可读名称时使用厂商与机型，最后使用通用 Android 名称。内部 ID 传入 gRPC `GetIdentity.id`、NSD TXT 的 `id`、本地媒体归属及 SQLite 对端主键；人类可读名称传入 `GetIdentity.name` 和 NSD TXT 的 `name`。刷新名称不会改变身份或重启 gRPC 服务。

设备列表、筛选与相册来源显示设备名，内部选中状态仍使用 ID。名称可以相同或被用户修改，不能用作数据库主键；IP 和端口也只表示当前连接地址。相同名称的设备以各自 ID 保存，不会混合媒体。

## 记住对端

`peers.id` 保持作为唯一键。发现设备后先通过 gRPC 核验身份，再保存名称、地址和同步信息；自动发现的新设备以「待确认」保存，用户确认后才同步，也可以在设备页面忘记设备，详见 [新设备确认、上线重试与忘记设备](新设备确认与忘记设备.md)。同一 ID 换 IP 或改名时更新原记录，保留已有媒体归属；已记住的地址如果返回另一个 ID，则拒绝将其当作原设备。离线时仍能读取本地保存的设备名及媒体缓存。

例如 A 已保存 B 的记录，B 清除应用数据或以同签名重装后，仍能读取相同的系统标识；重新发现 B 时，A 会更新原有记录。B 需要重新选择分享目录，A 随后根据 B 当前的完整目录快照更新增删。

稳定身份不等于备份：A 自己清除应用数据或重建整个媒体数据库，会丢失 A 保存的对端列表、设置及缓存，需重新发现。本次保留 v1.0.0 前数据库可以清空重建的策略，不新增独立设备列表存储或历史数据迁移。

## 稳定范围与版本边界

`ANDROID_ID` 取决于应用签名密钥、系统用户和设备。同一用户和签名下，应用重启、媒体库重建、清除本应用数据及卸载重装不会主动生成新的设备身份；恢复出厂设置、更换用户或签名则可能得到不同标识。debug 与 release 通常使用不同签名，因此不能假设两者身份相同。

参考：[Android ANDROID_ID API](https://developer.android.com/reference/android/provider/Settings.Secure#ANDROID_ID)、[Android 标识与重装行为](https://developer.android.com/about/versions/oreo/android-8.0-changes#privacy-all)。

此改动无需修改 protobuf 字段或数据库结构；既有设备 ID 字段仍为字符串。旧版的随机 UUID 不转换或合并为系统 ID。从旧版试用切换时，如保留了旧设备记录，应清空不兼容的应用数据并重新选择目录、发现设备。稳定身份用于局域网识别，不提供认证；当前无鉴权的协议范围不变。

## 验证

- Kotlin：系统 ID 规范化、非法值与读取异常、设备名及回退行为。
- Flutter 平台通道：获取有效 ID，拒绝空值及非法值，正确传递原生读取错误。
- 控制器与真实 loopback gRPC：广播、RPC 和媒体归属使用同一系统 ID；重建本地存储后身份保持；读取失败可刷新恢复；改名更新名称且身份与端口不变。
- 对端与 UI：同 ID 换地址/名称保留单个设备及媒体归属，同名不同 ID 可独立筛选；界面显示名称，不显示内部 Android ID。

两台 Android 16+ 真机仍需验证：A 记住 B 后，分别清除 B 数据、同签名卸载重装 B，重新发现时 A 不新增重复设备；B 重选分享目录后更新媒体快照；修改 B 的系统设备名后两端刷新显示新名；清除 A 数据后应重新发现设备。本地单元测试不等同于这些系统及跨设备验收。

2026-10-10 本地验证：本次身份改动完成时，140 项 Flutter 测试通过，34 项 Android 单元测试通过，Dart 格式检查与 `flutter analyze` 通过，`flutter build apk --debug --no-pub` 集成构建成功。未执行上述双机真机验收。

随后工作区出现并行的通知权限测试及关于页面改动：新增 Robolectric API 36 测试需要 Java 21+；使用本机较新 Java 复查时，Flutter 编译因关于页面引用的 `lib/app/app_info.dart` 尚未生成而中断。因此上述通过记录对应本次身份改动完成时的工作区，不代表后续并行改动已通过全部验证。
